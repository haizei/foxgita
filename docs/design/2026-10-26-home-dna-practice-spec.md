# Gita：首页偏好、Guitar DNA 与双入口练习闭环

## 2026-10-27 首页入口调整

本节替代下文关于底部启动今日清单的旧规则：底部主按钮改为「创建练习」，始终打开与标题旁「＋」相同的创建弹窗，包含名称、时长、项目归属、拍照和相册入口。确认创建后进入新练习详情，取消不会新增练习，也不会启动或恢复清单训练。顶部方案播放入口保持原行为；今日清单中的练习逐项开始或继续。今日练习标题旁不再显示项目数和总分钟数，创建按钮上方不显示用于启动清单的超预算提示。

## Problem Statement

用户在首页同时看到顶部「推荐方案」、中间「今日练习清单」和下方「为你推荐」，却无法明确它们的来源、相互关系及两个开始按钮的执行范围。未填写偏好时已经出现个性化方案，首页的「弹唱／初级／每天20分钟」与问卷生成的30分钟即兴方案也没有一致的生效规则。

填写或修改问卷、保存方案失败、暂停后切换练习、提前结束以及跨天继续时，用户需要确信自己的安排不会被覆盖、进度不会丢失、实际时长不会重复统计。现有 Figma 中主流程首页与 Guitar DNA 内的首页、训练和记录状态尚未按同一套规则统一。

## Solution

建立「同一份练习偏好、两种推荐用途、两个独立执行入口」的体验。首次补充信息和后续调整偏好统一进入 Guitar DNA 八题问卷；顶部提供可连续执行的整套推荐方案，下方提供可以主动加入今日清单的单项推荐。底部按钮只启动今日清单，顶部播放按钮只启动整套方案。

通过明确的通用方案、问卷草稿、已生效偏好、方案草稿、已保存方案和训练状态，让用户知道什么已生效、什么仍待确认。所有记录以实际练习明细为依据，方案训练汇总只是聚合展示；暂停、跳过及未发生的计划时间不计入实际时长。

## User Stories

1. 作为首次使用 Gita 的练习者，我希望尚未填写偏好时看到明确标记的「通用方案」，以便知道它不是根据我的答案生成的结果。
2. 作为练习者，我希望保留首页顶部的连续练习与方案组合卡，以便同时查看练习连续性和整套练习入口。
3. 作为练习者，我希望在今日清单下方看到「根据偏好，找到适合你的练习」，以便知道在哪里补充信息。
4. 作为练习者，我希望点击「补充信息」进入 Guitar DNA 八题问卷，以便集中表达自己的音乐方向和时间安排。
5. 作为已有偏好的练习者，我希望点击「调整偏好」修改同一份问卷答案，以便避免维护两套互相矛盾的信息。
6. 作为练习者，我希望问卷涵盖演奏愿景、灵感来源、演奏特质、练习时间、当前状态、优先改善、风格偏好和理想能力，以便推荐有明确的偏好依据。
7. 作为练习者，我希望沿用问卷已有的必选、可跳过和返回修改规则，以便按自己的情况完成填写。
8. 作为没有选择吉他手的练习者，我希望可以跳过相应特质问题，以便不因缺少偶像而无法继续。
9. 作为练习者，我希望在提交前核对并修改答案，以便确认用于推荐的信息正确。
10. 作为中途退出问卷的练习者，我希望填写进度保留，以便之后继续。
11. 作为已有偏好的练习者，我希望未提交的问卷修改不改变已生效偏好，以便暂存想法不会影响当前安排。
12. 作为练习者，我希望答案提交成功后才更新偏好，以便失败或中途退出不会造成隐式变化。
13. 作为练习者，我希望 Guitar DNA 结果明确表达练习方向而非演奏能力评分，以便正确理解结果。
14. 作为完成问卷的练习者，我希望预览方案的分段、主题、时长与推荐理由，以便决定是否采用。
15. 作为练习者，我希望编辑方案后主动保存，以便控制首页何时替换为新方案。
16. 作为尚未保存方案的练习者，我希望首页继续展示原方案，以便预览不会直接改变当前安排。
17. 作为保存失败的练习者，我希望方案草稿保留，以便无需重新编辑。
18. 作为保存失败的练习者，我希望重试保存当前草稿时不重新生成，以便结果和我的修改保持一致。
19. 作为已有个性化偏好的练习者，我希望下方「为你推荐」展示单项候选及其时长，以便逐项选择训练内容。
20. 作为练习者，我希望顶部整套方案和下方候选使用同一份已生效偏好，以便理解它们为什么适合我。
21. 作为练习者，我希望只有主动添加候选后它才进入今日清单，以便保留对今日安排的控制。
22. 作为练习者，我希望已在今日清单中的候选显示「已添加」，以便避免重复添加。
23. 作为练习者，我希望点击「已添加」能定位到已有项，以便检查其安排而不新增一项。
24. 作为练习者，我希望不同训练内容可以分别添加，以便标题相近也能保留不同练习目标。
25. 作为修改偏好的练习者，我希望单项候选根据新偏好更新，以便看到新的选择。
26. 作为修改偏好的练习者，我希望新的整套方案先作为待确认草稿，以便与已有安排比较。
27. 作为编辑过方案的练习者，我希望偏好变化不自动覆盖已保存方案，以便保留自己的调整。
28. 作为已安排今日练习的练习者，我希望偏好变化不自动改写今日清单，以便当前安排保持可预期。
29. 作为正在训练的练习者，我希望偏好或方案更新不改写正在执行的内容，以便进度与目标保持一致。
30. 作为练习者，我希望点击底部「开始今日练习」只执行今日清单，以便知道本次会练什么。
31. 作为练习者，我希望点击顶部播放按钮只执行整套方案，以便不会额外混入自选清单。
32. 作为练习者，我希望两个各30分钟的安排不会隐式合并为60分钟，以便明确掌握时间投入。
33. 作为练习者，我希望生成的方案遵守问卷中的建议时间预算，以便符合我的可用时间。
34. 作为主动增加内容的练习者，我希望可以超出建议预算，以便按当天情况调整。
35. 作为超出预算的练习者，我希望看到超出的分钟数但仍可开始，以便作出知情选择。
36. 作为方案训练中的练习者，我希望按顺序继续分段并保留明细，以便理解整套训练进度。
37. 作为练习者，我希望可以跳过分段，以便根据当时情况调整训练。
38. 作为练习者，我希望可以提前结束方案并保留已发生的练习，以便不必为了保存进度而完成全部分段。
39. 作为提前结束的练习者，我希望汇总显示「部分完成」和完成分段数，以便记录反映实际结果。
40. 作为练习者，我希望跳过的分段不被计入练习时长，以便统计可信。
41. 作为暂停训练的练习者，我希望暂停期间不计时且进度保留，以便稍后继续。
42. 作为暂停方案的练习者，我希望可以开始今日清单，以便临时切换练习内容。
43. 作为切换入口的练习者，我希望同一时刻只允许一处计时，以便不会重复累计时间。
44. 作为返回原方案的练习者，我希望可以继续原有进度，以便不必重新开始。
45. 作为隔天继续的练习者，我希望昨天的练习归昨天、今天的练习归今天，以便每日统计准确。
46. 作为隔天继续的练习者，我希望方案汇总仍能查看两天的相关明细，以便保留一次连续安排的上下文。
47. 作为两个入口都包含相同内容的练习者，我希望它们分别保留目标和完成状态，以便完成其中一个不会擅自勾选另一个。
48. 作为查看记录的练习者，我希望每个分段有实际练习明细且注明入口，以便追溯训练来源。
49. 作为查看记录的练习者，我希望一次方案训练可聚合查看，以便复盘整套安排。
50. 作为查看统计的练习者，我希望方案汇总不再额外计入一份时长，以便避免重复计算。
51. 作为查看历史的练习者，我希望后续编辑方案不会覆盖已发生的事实，以便历史仍反映当时训练。
52. 作为使用主流程和问卷流程的练习者，我希望两处首页及其返回状态遵循同一套规则，以便不会因入口不同而看到互相矛盾的结果。

## Implementation Decisions

### 领域边界与现有实现

- 本规格面向 Gita 正式应用与对应 Figma 设计。现有应用使用 SwiftUI、SwiftData、统一练习写入入口及按练习日期生成的首页与记录投影。首页状态、练习计时与记录聚合已有测试基础，应在这些边界上演进。
- Exercio 的问卷及训练演示可作为交互参考，但其独立领域模型和固定演示数据不能直接成为 Gita 的生产规则。本规格不要求整体移植该演示应用。
- 遵守已确认的偏好统一与执行范围决策，以及实际练习明细聚合决策。不引入独立 Session 作为新的计时事实；方案训练汇总属于明细的关联与投影，不是另一份可相加的时长。
- 分开表达安排中的目标时长、当前分段剩余时间和实际练习时长。既有倒计时的复位、完成和显示变化不得减少或替代持久化实际时长；本规格不改写倒计时与节拍器的既有音频契约。

### 模块与状态职责

- 首页展示负责连续练习与方案组合卡、今日清单、偏好入口或单项推荐以及两个独立开始入口。
- 偏好采集负责八题问卷、填写进度、答案确认及提交结果；问卷草稿与已生效偏好是不同状态，成功提交才更新后者。
- 方案管理负责通用方案、个性化预览、方案草稿、编辑与主动保存；方案保存成功才替换首页当前方案。
- 单项推荐负责依据已生效偏好展示候选，以及「添加／已添加／定位已有项」行为。重复判断依据训练内容身份，不能仅凭显示标题将不同训练内容视为同一项。
- 练习执行负责入口范围、分段推进、暂停、切换、跳过与主动结束；方案配置变化不能回写正在进行的训练。
- 记录展示负责练习明细、日期和入口归属、方案训练汇总与复盘入口；不复制汇总时长成为另一条计时事实。
- 需要表达方案与分段、实际练习明细、来源入口及训练汇总之间的关联，并保留当时实际执行的内容。具体持久化结构和迁移版本由实现根据现有模型确定，本规格不预定字段名、Schema 版本或网络端点。

### 首页与偏好生效规则

| 用户状态 | 顶部方案 | 下方区域 | 生效条件 |
| --- | --- | --- | --- |
| 尚未完善偏好 | 标为「通用方案」 | 补充信息入口 | 不将示例方案描述为个性化结果 |
| 问卷填写中或修改未提交 | 保持当前方案 | 按原已生效偏好展示；无已生效偏好时保持入口 | 保存填写进度不等于提交偏好 |
| 问卷提交成功、方案未保存 | 保持原方案，可进入新方案预览 | 根据已生效偏好更新单项候选 | 偏好提交与方案保存分别生效 |
| 新方案保存成功 | 展示用户确认保存的方案 | 继续展示单项候选 | 主动保存成功才替换 |
| 方案保存失败 | 保持原方案 | 不因保存失败丢弃已成功提交的偏好 | 保留草稿，重试保存不重新生成 |

- Guitar DNA 使用现有八题结构与单选必选、多选可跳过、返回修改和未选吉他手时跳过特质的交互。结果雷达与文案表达练习偏好和方向，不得声称是当前能力测评。
- 修改偏好更新单项候选并生成待确认的新方案，不自动覆盖已保存方案、今日清单或当前训练。
- 新偏好与仍保留的旧方案可以暂时并存；界面应区分当前已保存方案和待确认的新建议，不将旧方案描述成已经按新偏好更新。
- 单项候选仅在用户主动添加后加入今日清单。同内容已添加时显示「已添加」，点击定位已有项，不再创建、不增加目标时长。

### 执行范围与时间预算

- 底部「开始今日练习」只启动今日清单；顶部播放按钮只启动整套方案。两者不自动相互追加或合并时长。
- 问卷中的单次可用时间属于建议时间预算。生成方案必须遵守该预算；用户主动编辑方案或今日清单可以超出，展示超出分钟数并允许继续开始。
- 同样的训练内容出现在两个入口时，分别保留目标与完成状态，不因另一个入口的练习自动标记完成。
- 可以跳过分段和提前结束。保留已经发生的明细，展示完成分段数；提前结束为「部分完成」，跳过不计时，不把计划时长当作实练时长。
- 暂停方案后可以开始今日清单；原方案保存暂停进度，新入口执行独立练习。只能有一个入口处于实际计时状态，返回原方案时可继续原进度。
- 跨天继续已暂停的训练时，从剩余分段继续；昨天的事实保留在昨天，今天发生的练习形成今天的明细。训练汇总可以关联多天明细，暂停间隔不计时，不往历史练习追加时长。

### 记录与设计同步

- 每个方案分段保留对应的实际练习明细及来源入口；汇总总时长等于其明细实际时长之和。统计遍历实际事实时不得再次加上汇总时长。
- 同内容从不同入口实际练习产生的明细，应保留各自来源；复用内容并不意味着同一段时间可以在两个入口重复记账。
- 保留现有有效练习事实的判定，不因生成方案、保存方案、添加候选或展示汇总而虚构已发生的练习。
- 统一主流程的「待完善偏好」与「为你推荐」首页，并同步 Guitar DNA 页内的首页、问卷返回、方案预览、保存成功与失败、分段训练、暂停、部分完成、跨天继续和记录明细状态。
- 保留已采纳的顶部组合卡、今日清单、下方偏好入口或推荐卡及底部导航。现有页面重合时更新对应画板；不同状态明确命名，不在同一位置叠放新旧版本。
- 所有关键文案、卡片、按钮、状态和导航保持可编辑；不能用整张截图代替交付图层。页面应能完整展示恢复的下方模块，通过合理画板高度或滚动安排避免内容被按钮遮挡。

## Testing Decisions

- 用户已确认以「首页 → 问卷 → 方案／今日清单 → 练习 → 记录」完整用户旅程为主要验收边界。优先扩展 Gita 已有 XCTest 应用 UI 旅程测试，不另起演示应用作为正式验收入口。
- 好的测试执行用户可触发的操作，验证页面状态、安排是否改变、进度是否保留以及最终记录结果。不要断言私有字段、内部调用次数、视图树层级或与实现逐行对应的细节。
- 被验收的模块包括首页展示、问卷与偏好提交、方案预览编辑保存、单项推荐添加、两个练习执行入口及记录汇总。它们共同通过一个应用用户旅程入口接受验收，避免为每个页面另造测试边界。
- 先例：现有 PracticeFlowUITests 已覆盖应用启动、创建练习、进入详情和界面截图附件；PracticeHomeStateTests 已覆盖指定日期筛选、实际时长汇总与今日／历史 CTA；PracticeTimerTests 使用可控时间覆盖暂停排除和恢复累计。必要的确定性日期与时长回归沿用现有方式，不以等待真实跨夜或长时间休眠验证规则。
- 失败场景应通过测试环境提供可控的提交或保存失败结果；时钟仅在测试环境可控。测试工具不能改变生产行为，也不需要引入新的公开业务 API。
- 当前旧 UI 测试存在「启动不显示固定练习模板」及「主按钮打开创建练习」等断言，与本次设计目标存在演进差异；应按本规格更新相关期望，同时保留不把示例内容伪装为真实用户练习的约束，不能简单删除回归覆盖。

### 用户旅程验收场景

| 场景 | 操作与可观察结果 |
| --- | --- |
| 首次进入 | 无已生效偏好时顶部标为通用方案，下方显示补充入口，没有伪造个性化依据；下方卡片和底部操作不互相遮挡。 |
| 八题与跳过 | 从补充信息进入八题，单选未选不可继续；可跳过的题目可以继续，未选吉他手时仍能完成流程。 |
| 草稿退出 | 填写一部分后退出再进入，答案与进度保留；修改旧偏好但未提交时，原偏好和原方案保持有效。 |
| 偏好提交与方案预览 | 成功提交后下方候选使用新偏好，顶部原方案保持；雷达与结果说明不是能力评分。 |
| 保存成功 | 编辑并保存新方案后，主流程和问卷返回首页均展示同一个已保存方案，仍保留今日清单和单项候选。 |
| 保存失败重试 | 注入一次保存失败，草稿及用户编辑保留、顶部原方案不变；重试后保存同一份草稿，不换成另一份生成结果。 |
| 更新保护 | 修改偏好前准备已编辑方案、今日清单及暂停或进行中的训练；提交后只更新候选和新方案草稿，不改写已有安排与进度。 |
| 主动添加与去重 | 同一候选连续添加只出现一个对应清单项，状态为已添加；点击定位已有项，数量和目标时长不再增加；不同内容可以分别添加。 |
| 双入口隔离 | 清单和方案各30分钟，分别点击两个开始入口时，只看到对应的内容与目标，不出现合并的60分钟训练。 |
| 时间预算 | 以20分钟预算生成时方案合计不超预算；用户手动编辑为30分钟时提示超出10分钟，仍允许开始。 |
| 跳过与部分完成 | 完成部分训练、跳过一段并提前结束；汇总显示部分完成及真实完成段数，跳过和未练部分不贡献计划时长。 |
| 暂停与入口切换 | 方案实练60秒后暂停，暂停300秒不增加时长；今日清单实练30秒后返回，方案进度仍为60秒且可继续，各明细与合计只包含实际练习时间。 |
| 跨天继续 | 前一天实练后暂停，测试日期推进到次日并继续；前日明细不被追加，次日明细归次日，方案汇总关联两天且不计隔夜暂停。 |
| 同内容独立目标 | 清单和方案都包含同一训练，完成方案中的训练不自动完成清单中的训练；查看记录能够区分来源。 |
| 聚合不重复计时 | 四段实际明细为9、8、7、6分钟时，方案汇总为30分钟，相关每日统计仍只累计30分钟，不能成为60分钟。 |
| 历史稳定 | 保存记录后修改偏好、编辑或替换方案，历史明细的内容、入口、日期及已发生时长保持原事实。 |
| Figma 一致性 | 对照相同状态检查两个主流程首页及问卷内返回首页，文案、方案状态、操作范围一致，无文字裁切或重合画板；确认关键内容为可编辑图层。 |

这些是后续实施必须通过的验收标准，本次只编写并发布规格，未声称对应功能或测试已经实现、运行或通过。
