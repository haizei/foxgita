# 谱图导入到训练谱：技术方案

状态：建议实施，尚未上线。首个交付范围为清晰印刷吉他六线谱；以《晴天》验证整页流程，用其他曲谱检验泛化。五线谱保留独立识别入口，不套用 TAB 的弦品规则。照片和 PDF 均要测试。

## 决策依据

[Flash 与 Max 的同图实测](../qa/2026-11-03-score-flash-simulator.md)只识别了《晴天》首行与页眉，各一次，均为同一模拟器、medium、600 秒上限，输入图像字节相同。Flash 用 71.1 秒，上传 0.47 秒，等待响应约 70.4 秒；返回 4/5 小节、9 个事件，45 个返回音符中 10 个 MIDI 与弦品冲突。Max 用 482.8 秒，返回 5/5 小节、44 个事件，仍有 24 个音符内部冲突。两者 HTTP 200，均不能直接用于精确跟练。另一次真机 low 虽在约 91 秒返回，却只给出 3 小节。不能把响应等待进一步精确归因为排队或纯推理，也不能用小节数计算逐音准确率。

因此分别处理等待、漏读和错误生成。缩图不是这里首要的提速手段，小符号反而怕丢失；把超时改成十分钟能拿到部分慢响应，却不能解决漏谱。Flash 作为小块转写的首个试验候选，不直接替换生产默认。Max 只作为疑难块的对照候选，其收益要单独测量。

## 一次导入怎么走

1. 用户选谱后立即看到页预览。端上生成 sourceID、持久的提交键、谱页指纹；用户确认上传后才提交。生产由识谱服务使用运营方密钥，模型名和凭据不再是普通用户的设置步骤。HTTPS 服务部署及产品会话令牌发行是正式上线前置条件。
2. 服务接收并检查谱页后返回 202 和 jobID。客户端把 jobID、sourceID、用户、协议版本和最近进度落盘；若服务已接收但回包丢失，用同一提交键和内容找回同一任务。用户可离开页面，回到曲谱库看到“已识别 3/5 行，1 处待核对”一类的实际进度。
3. 服务按照已确认的清单调度小块。首版端上复用已有谱行裁切，扩展小节边界检测；服务校验坐标范围、单位 ID 和图片指纹，从相同规范的页图取得裁片。每个结果保留原页归一化坐标。页眉只读一次，把速度、拍号、调弦和 capo 候选作为共享上下文。
4. 模型只转写可见音乐符号；程序编译为训练事件，检查缺块、节奏、可演奏性。正常块直接进入草稿；不确定块带原图位置交给校正页。全部结构可用且用户确认后，发布一个训练谱版本。版本用于播放、循环、选段和评分，不再为每次练习调用模型。

## 识别单位、数据与规则

**先确定要读哪些小节，再让模型读内容。** 从谱线的上下边界、贯穿谱线的纵线及相邻空白提出小节边界；区分小节线、音符符干、双线、反复线。切片在上下保留和弦图、下方声部和符梁，左右留上下文，但只输出指定 ID 范围，避免重叠重复。试验比较同一行按单小节、相邻两小节和整行三种输入；不默认每小节单发最快。拍照倾斜、切掉谱边或小节线检测不可靠时，显示边界让用户调整，或回退为整行待核对。不得用同一次模型回答的“小节数”反过来证明它没漏小节。

建议增加中间结构 PrintedBar，和可播放的 ScoreDocument 分开。模型输出示意（字段为建议，非当前 API）：

```json
{"barID":"p1-r1-b1","voice":1,"symbols":[
  {"kind":"hammerOn","string":3,"fromFret":0,"toFret":2,
   "duration":null,"box":[0.48,0.32,0.08,0.18],
   "review":["duration","string"]}
]}
```

- PrintedBar 保留印刷品数、弦号、和弦标记、休止、扫弦方向、击弦、延音、声部、时值及位置；未知填 null。模型不得用整小节和弦替换无法辨认的节奏。示意中的值不是对原谱的人工标注。
- 编译器把确定的节奏换算为 960 ticks/四分音符；TAB 的音高由“对应空弦 MIDI + 确认的 capo + 品数”计算。例如标准调弦、capo=0 时，五弦三品必为 48。缺品数、特殊调弦或多个 capo 选项时保留待确认，不能补零蒙混过关。程序消除算术冲突，但不能纠正看错弦、读错品的错误。
- 独立清单检查 ID 覆盖、重复、声部、拍号和每声部节奏位置；检查时区分同时发声的和弦、延音、休止、弱起和反复，不能简单累加多个声部的时值。先校验印刷小节，确认反复结构后生成播放顺序。《晴天》首行 5 小节、20 拍是该样本的独立预期，不是通用常量。
- 扫弦方向 / 闷音等如果播放器或评分器尚不能表达，保留原始符号并标出能力限制。阻断精确评分；可单独提供经用户确认的节奏练习，清楚说明其范围。不得把近似和弦稿标为逐音跟练谱。

## 任务、失败和恢复协议

保留 v1 页级协议给旧客户端。新协议按版本协商；POST 返回 jobID，GET 返回阶段、已完成/总块数、每块状态、安全错误码和可用草稿版本；重试接口接收 jobID、目标块、幂等键。客户端按活动页面退避轮询，回到前台立即查询一次。进度由完成块数计算，不把无输出时间显示为上传中。

建议任务状态：排队 → 处理 → 待校正 → 已确认；另有待补传、可重试失败、取消、过期。待校正草稿可以包含未解符号，但与可练版本分库存或分状态保存。块级表保存用户、任务、逻辑小节 ID、裁图指纹、布局/模型/提示词/协议版本、尝试次数、租约、状态和结果引用。按稳定 ID 合并，不能按网络返回顺序合并；新一轮尝试用 generation 拒绝迟到旧结果。

| 故障 | 处理 |
|---|---|
| 页面关闭、手机锁屏、查询断网 | 只停止刷新；后台服务继续工作，App 重开凭 jobID 恢复。提交回包丢失用原提交键找回，禁止新建重复任务。 |
| 服务重启 | 保持当前服务端不存原图的边界：成功块保留；未完成块标为待补传。App 恢复时从本地源库补传同指纹图像，再续跑。手机离线时不能承诺服务重启后自行完成。 |
| 429、暂时性 5xx、上传后迟迟不返回 | 工作线程设置独立时限与并发上限；429 遵从 Retry-After；建议每块最多一次自动重试，受作业总时限及费用上限约束。超时可能已产生费用，记录尝试，避免层层重发。401/403 直接提示服务配置问题。 |
| 漏块、坏 JSON、拍数冲突、近似转写 | 保留成功块与原图；仅失败块可重切或重识别一次；仍无解交用户校正。HTTP 成功不能被记为音乐质量通过。 |
| 用户取消、任务过期 | 取消排队块并拒收迟到结果。到期清理结果和临时资料；保留端上用户原件，显示可重新提交。 |

初版可沿用现有两个 worker，设每用户/全局上限，先测并发 1 和 2。分别配置提交、单次模型调用、整作业和查询期限；10 分钟只用于诊断，不当产品响应目标。用 jobID 关联上传完成、排队、供应商响应、编译、待校正时间；另记每块 Token、重试、模型版本、完整性与用户改动数。日志不保存密钥、谱图或思考正文。

## 如何生成可跟练的版本

校正页并排显示原图局部和转写结果，优先定位缺小节、含糊的弦品/时值和 capo。用户改一个值即重算相关音高或时间轴并可试听；不必因改变调夹重新请求模型。发布条件：目标范围的阻断项全部解决、编译成功、ScoreDocument.validate() 通过、有可发声音符、用户明确确认。发布时原子写入或可幂等恢复，避免“草稿已确认但曲库没谱”。将 sourceID、修订及 versionID 绑定；改谱生成新版本，不改写旧练习记录。跟练入口直接使用已确认版本与小节范围驱动 ScoreRuntimeModel；验收既要听播放，也要验证节拍光标、循环边界与练习记录归属。

## 实施次序与验收

| 阶段 | 改动 | 交付判据 |
|---|---|---|
| 1. 先跑通不丢任务的闭环 | 改 ScoreImportView、ScoreRecognitionClient、ScoreSourceVault 与 score-service；持久化 jobID，拆分查询/取消，补传复用成功结果 | 用固定供应商响应做可重复端到端测试：提交 → 关页面/杀 App → 再开恢复 → 校正 → 发布 → 指定小节循环并保存练习。故障注入覆盖丢 202 回包、查询失败、worker 重启；验证不误删任务、不重复调用成功块。 |
| 2. 验证模型真正能读对 | 给《晴天》首行逐事件人工标注，明确可见事实与歧义；实现独立小节清单、PrintedBar、编译器及校正定位。在相同素材上跑 Flash 整行 / 两小节 / 单小节，计入总调用量 | 首行 5/5、20 拍，音高公式零冲突；击弦、扫弦、时值与标注逐项对照。切分导致的漏音、重复音也计错。不能只验 JSON 或看模型自报置信度。 |
| 3. 验证整页与上线 | 接入正式后端会话、HTTPS、限额和监控；用同张谱完整五行跑一次，再用未参与调试的不同排版、PDF、手机照片验收 | 所有源小节都被覆盖或显式阻断；未确认稿不得进入精确评分。人工在模拟器和真机各完成一次从导入到跟练。失败块单独重试，成功块无重复计费调用。 |

建议先以 20 页留出样本做工程筛查，按印刷 TAB / 照片及谱面难度分组，五线谱另评。用两人复核的事件标注，比较弦品、归一化起拍与时值、奏法；报告漏音、增音、事件 precision/recall、需人工修改的小节比例。歧义样本单列，不能把所有难例剔除后报告准确率。每个方案同时报告每页总费用、端到端 P50/P95、首个可核对块的时间和确认一页的人工耗时。初版验收目标：已接收上传后两秒内返回任务号（P95，不含上传）；已确认谱零未解阻断项；故障注入场景可恢复。识谱精度与整页耗时目标在人工基线和首轮盲测后确定；一次 71 秒首行样本不能预测整页耗时。

通过功能开关按导入来源逐步启用新协议；保留现有已确认曲谱的读取及播放，不迁移旧练习数据。若 Flash 小块方案仍主要输出和弦摘要，停止扩大调用，保留后台和校正流程，替换“符号识别”一步，评估能输出吉他 TAB 事件的专用识谱器。是否采用以同一标注集、同一验收标准决定。
