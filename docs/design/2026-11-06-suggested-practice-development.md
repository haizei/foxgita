# 建议练习｜开发追问与实现范围

日期：2026-11-06。Q7–Q12 已全部回答，用户已明确确认完整开发范围。实现已接入 SwiftUI 应用，两个聊天的规则冲突已统一为本记录 Q8、Q11 的选择。40 项回归通过；末次取消回调保护修改后，36 项核心再次通过。实际验证与截图见 [QA 记录](../qa/2026-11-06-suggested-practice.md)。

用户目标：将已确认的 Gita 首页「建议练习」及其来源、确认和接续流程落地到现有 SwiftUI iOS 应用。设计基于 A1「今日练习 / 跟谱入口」，建议卡与今日练习同款；右侧说明不进入产品。

## 已确认的设计树

1. **内容来源**：已保存练习 → AI 总结事实并提炼一个重点 → 用户编辑并确认。AI 输入只含本次练习和所属项目当前重点，不读取全局记忆，不匹配、选择或更换练习。
2. **生成生命周期**：AI 可用且功能启用时完成后自动生成；不阻塞练习事实保存和离开。结果归属来源记录的未确认草稿，离开后可回看。新编辑不被旧异步结果覆盖。
3. **确认与归属**：默认只保存续练重点；可选一次性更新项目当前重点，不持续同步。首页只展示已确认重点。
4. **首页与执行**：无重点时不显示占位卡；待开始显示原文与来源；进入当天关联面板但不自动计时；明确完成后移出待练区。跨天建立当天事实，不向历史追加时长。
5. **本轮新增确认**：见 Q7–Q12；全部保留用户选择的推荐答案。

| 题目 | 用户选择及开发约束 |
|---|---|
| Q7 信息不足 | 有明确练习对象但无反馈时可以生成延续建议，不诊断表现；连练习对象也不明确时才请求补充 |
| Q8 数量 | 每份档案最多一条未完成行动；保存新重点时明确选择保留旧重点或替换，失败保留旧内容 |
| Q9 意图冲突 | 本次用户明确写出的下次安排优先，项目重点作为背景；不反向覆盖用户意图 |
| Q10 依据变化 | 保留草稿及人工编辑，提示原记录或项目重点已变化；用户决定继续编辑保存或重新生成 |
| Q11 项目失败 | 续练重点已保存则保持有效；项目冲突或失败单独表达、处理和重试，冲突时先展示最新值再决定覆盖 |
| Q12 首页进行中 | 沿用离开单项面板即暂停；首页显示「已暂停／继续」，进入原面板后由用户明确恢复；不新增首页持续计时 |

## 开工时的代码事实

- `PracticeDetailView.complete` 先保存笔记、媒体与练习事实，标记完成后直接退出，尚未接入练后重点弹层。
- 没有独立的下次重点草稿或已确认行动持久化；既有录音复盘 `reviewNextAction` 不等于用户采纳。
- `PracticeStore.createPracticeItem` 可创建零时长当天练习，支持来源身份及可选项目；`savePracticeItem` 使用绝对累计时长，继续复用该边界。
- `PracticeEntryGate` 的内存防重不足以覆盖重启，需要持久行动身份及当天关联来防止重复创建；不按标题判断是否同一行动。
- 旧 `NextSessionClient` 生成带预算的整项练习并读取全局记忆；新练后重点不能直接复用其语义。可复用 AITransport 的请求与错误处理基础设施。
- 离开 `PracticeDetailView` 会暂停计时，重进也保持暂停，故首页稿中的实时计时文案应按 Q12 调整。
- 单项明确完成通过 `AppRouter.completedPracticeItemIds` 表达，首页行另查方案清单完成状态。实现须以关联练习的明确完成事件判断行动结束，不能用时长或方案分段完成代替。
- `updateProjectFocus` 已支持更新，但没有旧值比较与冲突处理；项目重点最多 120 字，应显式校验，不静默截断用户内容。

## 实现边界

- 按档案保存草稿、确认行动、来源、依据快照、编辑版本、当天执行关联与跳过日期。
- 独立的练后文本生成与输出校验，不读取全局记忆；应用作用域任务负责离开后结果归档及过时结果保护。
- 练习完成成功后衔接紧凑底部弹层；支持编辑、复盘往返、保存、返回、信息不足补充、失败重试与明确替换。
- 首页「建议练习」复用现有任务卡视觉；支持开始、暂停后继续、来源回看、修改、跳过及撤销、删除与失败提示。
- 项目重点可选更新、冲突提示与单独失败重试；未确认草稿不出现在首页。
- 保持现有偏好推荐区域、整套方案、项目和曲谱各自语义；保留既有材料引用，不扩展练习匹配或教学内容生成。

## 验证范围

- 模型解析、依据范围和信息不足处理；没有真实媒体分析时不生成演奏判断。
- 草稿重入、编辑竞态、依据变化、AI 失败与禁用后的手动降级。
- 单条约束、替换／跳过／删除失败、重启防重、重复开始、跨天归属及实际时长只保存一次。
- 保存重点成功但项目更新失败、项目冲突后的单独处理。
- 首页 → 当天练习 → 完成 → 确认重点 → 首页 → 同日接续／隔日新练习的交互与视觉验证。

## 实现记录

- 新增 `NextFocusStore`：按档案原子写入 JSON，来源记录保存未确认草稿，首页独立保存一条已确认行动；读失败不覆盖原文件。测试和恢复测试使用隔离目录。
- 新增 `NextFocusClient` 和 `practice.next_focus` skill：输入只有本次已保存事实、可用分析和项目当前重点；不接入记忆 provider，调用日志的 memoryIds 为空。旧 nextSession 的输入、输出和记忆范围保持独立。
- 新增 `NextFocusEditor`：完成后自动整理、手动降级、草稿重入、依据变化提示、编辑保护、明确替换、复盘往返及可选项目更新。项目更新失败独立保留待处理操作，覆盖时核对用户刚查看的项目重点值。
- 新增 `SuggestedPracticeSection`：复用今日练习的 `DaySessionCard`，无行动不占位；暂停后「继续」进入同一项，不自动续计时。修改、来源、跳过撤销和删除均有可见失败提示。
- 行动使用稳定 origin 定位同一天实际练习；创建成功但关联写失败时，重启后重试复用原项。跨天创建新事实，明确完成与行动移除一起记录可恢复的执行标识。已完成、删除或替换的行动重新确认时获得新身份，不复用已结束执行。
- 未保存编辑会阻止滑动关闭；返回或重新生成前需先重试保存，避免磁盘恢复后丢失输入。生成失败保留旧依据，不将旧结果标成新来源。
- 最终 40 项（36 核心、4 界面）通过，末次取消回调保护修改后 36 项核心再次通过。完成流程、生成待确认、信息不足补充、首页待开始和暂停继续均有通过记录；截图已导出并核对。项目重试独立于行动确认，保存失败的编辑也会使旧生成失效，相关回归及独立审查均通过。
