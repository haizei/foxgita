## 代码事实

- SwiftUI / Observation / SwiftData，最低 iOS 18，当前 schema V19。
- PracticeStore 负责写入和业务命令；PracticeRepository 当前由本地 SwiftData 实现。
- 未发现练习数据 CRUD、云同步或独立服务端工程；网络层主要为用户配置的 AI chat/completions 传输。
- PracticeItem 保存实际练习事实、单份文本笔记、累计时长、一套节拍器参数及媒体关系。
- 步骤是 JSON 字符串数组，没有步骤实体、独立 ID、计时或声音配置。Project 没有节拍器配置字段。
- 七音色、14份普通拍/强拍 WAV、音量、试听、强拍增强、TAP、变速训练、四态重音、8种细分已真实实现。
- 拍号/重音/细分在音频时间线的小节边界原子切换；声音/音量即时更新。
- 实际累计时长与倒计时分离；倒计时是当前详情访问临时态。到零停播放、暂停实际计时、结束保存录音，但不自动完成练习。
- 语音输入是设备端语音转文字，区别于保存录音附件；现实现开始识别会暂停练习并结束保存当前录音。
- 图片最多3张，本地文件归属 PracticeItem；笔记是每条练习的一份文本。
- 业务 App 字体为系统字体与 Dynamic Type；Figma 的 Noto Sans SC 是预览字体。
- 新版底座/开关生成图片尚未进入 iOS Assets。

### 第二轮提问前发现的差异（已由 Q8–Q13 解决）

- PR-01 主卡只有拍号、速度与细分，没有音色/视觉设置的可见入口或指向 MT-04 的原型连接，需要确定入口与关闭方式。
- 新 MT-03 可改变分母，但当前代码只保留、显示分母；UI 无分母入口，分母不参与时钟计算。当前主拍间隔恒为 60/BPM 秒，支持的分母需明确限制。
- 当前练习计时只在节拍器启动成功后开始；单独录音不会启动练习计时，可能形成有录音而实际时长为零的记录。
- 主计时暂停不暂停录音；录音有独立暂停/继续，停止才形成附件。录像使用系统相机，未保证录像过程中练习计时和节拍器连续。
- 录音波形当前为静态装饰；Figma 未说明输入来源。导入文件也没有类型、容量或失败状态定义。
- 当时小节计数的起点、暂停/复位边界、预备小节是否计入及显示位置没有定义，现按 Q11 实施。
- 当时播放中更换音色、编号与卡片状态、临时静音的计时关系没有定义，现按 Q12 实施。

### 第二轮已确认（Q8–Q13）

| 编号 | 问题 | 用户已采纳方案 |
| --- | --- | --- |
| Q8 | 主卡如何进入音效与视觉设置、如何关闭？ | 主卡右上角齿轮打开完整 MT-04；面板提供明确关闭入口并支持下滑收起，装饰螺丝不承担操作。 |
| Q9 | 拍号分母和 BPM 单位如何对应？ | 分母限制为 2/4/8/16；BPM 按当前分母代表的音符计拍，显示对应音符单位；6/8、120 BPM 表示每秒两个八分音符，不自动转换为附点四分音符。 |
| Q10 | 录音、录像与练习计时如何协作？ | 实际计时独立于节拍器；支持关闭节拍器练习；开始录音或录像时启动/继续实际计时。主暂停同时暂停录音；录音自身暂停只暂停录音，停止录音保存附件且不停止练习。录像期间继续实际计时、暂停节拍器，退出相机后由用户恢复声音。 |
| Q11 | 小节计数如何起算与重置？ | 主卡展示第 N 小节；正式播放第一小节从 1 开始，预备小节排除；暂停/继续保留，重置或新的播放轮次从 1 开始；只跟随真实节拍器时间线。 |
| Q12 | 预设编号、卡片与试听怎样联动？ | 七种预设按固定顺序编号 1–7，± 到两端停止；卡片与编号共享选择。未播放时试听两小节，不启动练习计时或倒计时；播放中切换从下一个发声事件使用新音色，不重启节拍、不叠加第二路试听；静音不停止计时。 |
| Q13 | 本轮附件导入和波形范围？ | 导入照片、音频、视频；沿用每条练习最多三张图片；PDF/乐谱解析另立需求；录音波形接真实麦克风电平，并实现权限拒绝、取消、导入失败的可恢复状态。 |

用户第二次回复“全部采纳”确认 Q8–Q13。已同步术语：Beat Unit、Bar Counter、Practice Elapsed Time、Countdown Run 与 Recording Segment。

产品决策树在 Q1–Q13 下已收敛。数据实现、短屏适配、无障碍及失败恢复由实施规格给出可验证方案；后台连续与中断手动恢复沿用已有 ADR。音色主观选择按 Q7 在可试听素材产出后评审，不提前宣称素材已获用户批准。
