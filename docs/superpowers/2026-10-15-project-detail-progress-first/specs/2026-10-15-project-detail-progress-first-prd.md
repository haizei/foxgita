## 1. 背景与产品定位

### 1.1 现状与痛点
在原有项目详情页中，信息架构被划分为「项目身份、完成目标、阶段槽位、练习轨迹」，并包含较重的设置项与尚未被验证的占位卡片：
1. **反馈滞后且缺乏听觉证据**：吉他练习是高度依赖听觉反馈的过程。原页面只能看到干瘪的累计时长与日期，用户无法直观“听见”自己相比两周前甚至一个月的音色、连贯度和节奏改善。
2. **机械量化打分引发心理焦虑**：探索方案中曾尝试过“阶段进度 65%”或“完成度 92%”等数字打分机制，但在乐器练习场景中，量化百分比既难以准确评估，又容易给自学者带来打卡焦虑与挫败感。
3. **行动断层**：用户进入项目详情往往带着“我接下来练什么”的疑问，旧设计将行动入口置于边缘，未能与今日练习计划无缝衔接。

### 1.2 核心理念与设计主旨
在经历「行动推进型 (01)」、「阶段路线型 (02)」、「成果档案型 (03)」三种设计方向的推敲后，最终收敛并采纳 **Progress First（先看见进步）** 方案：
- **定性演进代替数字打分**：通过 `Project Progress Story`（进步轨迹）呈现“从分段练，到完整弹一遍”的真实演进历程，强调练习范围与动作阶段，杜绝冷冰冰的打分。
- **让录音说话（听见变化）**：建立 `Last Practice Evidence`（上次练习证据）与 `Audio Comparison`（录音对比），支持 A/B 快速交替试听，辅以时间戳停顿差异分析与历史笔记印证。
- **状态机闭环驱动今日行动**：将 `Next Practice Focus`（下次练什么）与 `Project Practice State Handoff` 深度绑定，点击后依据今天是否开练自动流转，保障空练习不滥建、练习意图不断层。
- **单一真理源**：项目笔记作为关联练习记录的 `Project Note Projection`（只读投影），修改回到原练习记录，确保数据严谨与架构纯粹。

### 2.1 屏幕 01：项目详情 · 先看见进步 (Frame `1983:3`)

#### 页面布局与视觉规范
- **导航栏**：
  - 左侧：返回按钮（`‹`）
  - 中间：大标题「项目详情」
  - 右侧：更多操作按钮（`•••`，呼出编辑项目、置顶/取消置顶、归档/删除）
- **项目头信息**：
  - 项目名称：如「学会《知足》」（20pt Semibold）
  - 目标描述：如「跟着原唱稳定完成整首弹唱」（14pt Regular，次要文本色）

#### 核心模块 1：Progress Story（进步轨迹故事）
- **卡片容器**：白色背景，16pt 圆角，16pt 内边距。
- **主标题**：
  - 文本示例：「从分段练，到完整弹一遍」
  - 视觉：前段默认文字色，后段重点文字采用品牌橙色高亮。
- **定性原则标注**：
  - 辅助说明：「根据已记录的练习范围 · 非完成度评分」（12pt，中性灰色）
- **里程碑轴线（Milestone Timeline）**：
  - 水平排列 3 个里程碑节点（支持自动计算与提取）：
    - 节点 1：日期（如「10月3日」）+ 状态圆环 + 动作标签（如「分段练副歌」）
    - 连接线（实线）
    - 节点 2：日期（如「10月9日」）+ 状态圆环 + 动作标签（如「连贯弹唱」）
    - 连接线（高亮实线）
    - 节点 3：日期（如「10月13日」）+ 高亮实心圆环 + 动作标签（如「完整弹唱一遍」）
- **规则定义**：
  - 节点根据关联有效练习的标题、分段范围与标签特征自动聚合生成；
  - 节点仅代表练习范围从局部向整首的扩展，绝不呈现诸如“完成度 60%”等数字。

#### 核心模块 2：Last Practice Evidence（上次练习证据）
- **头部信息**：
  - 左侧标题：「上次练习」
  - 右侧元信息：日期与耗时，如「10月13日 · 18分钟」
- **内容主卡**：
  - 左侧图标：音乐徽标（圆形背景 + ♫ 图标）
  - 练习标题：如「完整弹唱一遍」
  - 练习内容摘要：「练习内容：副歌衔接、整首收尾」
  - 个人心得反思：「我的感受：可以连着弹完，收尾仍需稳定。」
- **内嵌音频播放条（Audio Player Bar）**：
  - 播放控制：圆形播放/暂停按钮
  - 波形可视化：22 根波形柱表达音频振幅轮廓，播放时高亮推进
  - 录音时长标签：如「录音 02:04」
  - 对照入口链接：右侧显示「与阶段版对照 ›」，点击进入 **屏幕 02（录音对比）**。

#### 核心模块 3：Next Practice Focus（下次练什么）
- **头部信息**：
  - 左侧标题：「下次练什么」
  - 右侧提示：「项目当前重点 · 可修改」（点击可快速呼出编辑重点 Sheet）
- **行动指引卡片**：
  - 左侧图标：同心靶心徽标（Target Badge）
  - 重点目标：如「收尾节奏稳定」
  - 指导说明：「先练收尾，再连弹整段副歌。」
  - 点击整卡：直接触发 **`Project Practice State Handoff`**，根据今日开练状态启动或恢复练习。

#### 核心模块 4：My Notes Preview（我的笔记预览）
- **头部信息**：
  - 左侧标题：「我的笔记」
  - 右侧入口：「查看全部 ›」，点击进入 **屏幕 03（我的笔记历史列表）**
- **笔记预览列表**：
  - 最多倒序展示前 3 条有效练习笔记；
  - 结构：日期（如「10月13日」）| 分隔竖线 | 笔记正文单行截断预览 | 右箭头（`›`）；
  - 点击单条：直接跳转至对应的原始练习详情页（`PracticeDetailView`）。

### 2.2 屏幕 02：录音对比 · 听见变化 (Frame `1983:4`)

#### 页面定位与入口
- **入口**：在屏幕 01 上次练习卡片中点击「与阶段版对照 ›」。
- **定位**：让用户在两个关键节点（基准阶段版 vs 最近一次练习）之间进行听觉比对，清晰感知练习带来的连贯度与节奏提升。

#### 模块详述
1. **导航栏**：
   - 左侧：返回（`‹`）
   - 中间：主标题「录音对比」，副标题「学会《知足》 · 副歌片段」
   - 右侧：文字按钮「更换录音」，点击弹出选择 Sheet，允许用户从该项目所有带录音的练习中任意重选对比版本 A 与版本 B。
2. **对比提示与周期**：
   - 主标语：「听听这段副歌的变化」
   - 对比周期：「10月3日 阶段版 → 10月13日 最近录音」
   - 范围提醒（Caveat Banner）：「ⓘ 两次均为用户确认的同一片段」
3. **双轨 A/B 播放器（Version A vs Version B）**：
   - **轨道 A（阶段版）**：
     - 版本标签：「阶段版」
     - 录制时间：「10月3日 · 22:14」
     - 范围标签：「副歌片段」
     - 独立播放键、32 柱波形条、时长「02:16」
   - **切换控制条**：
     - 居中胶囊按钮：「⇄ 交替听 A / B」，点击可在正在播放的 A 与 B 之间无缝交替切换。
   - **轨道 B（最近录音）**：
     - 版本标签：「最近录音」
     - 录制时间：「10月13日 · 20:37」
     - 范围标签：「副歌片段」
     - 独立播放键、32 柱波形条、时长「02:04」
4. **AI Audio Observation（AI 观察卡片）**：
   - 卡片顶部标头：「✦ AI 观察 · 基于这两段录音」
   - 核心结论：「最近一次副歌衔接更连贯；收尾仍有短暂停顿。」
   - 时间戳证据对照：
     - 左侧旧版本证据：`▶ 阶段版 00:42`（点击可跳至该秒试听），文字描述「可听到和弦切换处的停顿」；
     - 右侧新版本证据：`▶ 最近 00:38`（点击可跳至该秒试听），文字描述「衔接更连贯，但收尾仍有停顿」。
5. **本次对比引用的练习笔记**：
   - 标头：「▣ 我的笔记」，右侧链接「查看全部历史 ›」，副标「本次对比引用 2 条 · 项目共 3 条」
   - 早期笔记：10月3日 22:20「和弦切换总会停一下。」
   - 最近笔记：10月13日 20:45「这次可以连着弹完，收尾仍需稳定。」
6. **底部主行动按钮**：
   - 常驻底部 CTA：「继续这次练习」，点击执行 State Handoff 流转至今日练习，带着对比发现的弱点立即开练。

## 3. 业务逻辑与状态机 (Interaction & State Machines)

### 3.1 Project Practice State Handoff (项目到今日练习状态机)

项目详情页内的「下次练什么」行动卡片与录音对比页底部的「继续这次练习」按钮，统一遵循三状态机流转：

```
                    ┌─────────────────────────┐
                    │ 用户点击项目内行动主按钮 │
                    └────────────┬────────────┘
                                 │
             ┌───────────────────┼───────────────────┐
             ▼                   ▼                   ▼
     [状态 01：今天尚未开始]   [状态 02：今日已创建未完成]   [状态 03：今日已完成]
             │                   │                   │
   - 自动创建今日首条练习      - 复用未完成的今日练习条目     - 弹出确认/自动创建第 2 条
   - 标题预填项目当前重点      - 保留已记录的时长与状态       - 上次证据更新为今日第 1 条
   - 自动关联本 projectId      - 避免产生重复空练习 ID        - 标题继续预填当前重点
             │                   │                   │
             └───────────────────┼───────────────────┘
                                 ▼
                     ┌───────────────────────┐
                     │ 流转至练习页/练习工作台 │
                     └───────────────────────┘
```

1. **状态 01：今天尚未开始 (Today Not Started)**
   - 条件：今日日历天内，该项目下不存在有效的 `PracticeItem`。
   - 按钮主文案：「开始今天的练习」。
   - 行为：创建一条新的 `PracticeItem`（`date = 今日 00:00`，`projectId = 当前项目ID`，`title = 项目下次练什么目标`），直接导航至该练习详情开始计时/节拍器练习。
2. **状态 02：今日已创建未完成 (Today Created & In-Progress)**
   - 条件：今日日历天内，该项目已存在一条 `PracticeItem`，且 `isCompleted == false`。
   - 按钮主文案：「继续这次练习」。
   - 行为：直接复用并打开该条练习，不生成新的空白练习记录，防止多条无时长空练习泛滥。
3. **状态 03：今日已完成 (Today Completed)**
   - 条件：今日日历天内，该项目已存在至少一条已标记完成的练习。
   - 按钮主文案：「再练一次」。
   - 行为：将“上次练习证据”自动刷新为今天刚刚完成的练习成果，点击后创建今天第 2 条练习项，满足用户一天进行多次练习的需求。

### 3.2 对比基准版本选择逻辑 (Benchmark Selection)

进入录音对比页时，基准 A（阶段版）与当前 B（最近录音）的匹配规则如下：
1. **优先匹配明确阶段版**：
   - 检索项目中是否已由用户指定 `milestoneVersionItemId`。若存在且该练习音频文件存在，取该音频为 A；
2. **自动回退为首条有效录音**：
   - 若用户尚未设置阶段版，系统自动抓取该项目关联的历史练习中**最早一条**包含有效录音的练习项，作为初始基准 A；
3. **版本 B（最近录音）**：
   - 自动抓取该项目除 A 之外**最新一条**包含有效录音的练习项；
4. **更换录音（Change Recording）**：
   - 用户点击右上角「更换录音」时，弹出 ActionSheet / Half-Sheet，列出该项目下所有带音频的练习记录，用户可重新自由指定对比双方（Version A / Version B）。

---

### 3.3 A/B 音频播放与互斥策略

1. **单点互斥播放**：
   - 在项目详情页或对比页中，任何一个音频播放器开始播放，必须立即暂停其他正在播放的音频实例；
   - 退出页面或 App 进入后台时，试听播放器安全暂停（与节拍器的后台保活播放明确区分，试听音频不占后台音频会话）。
2. **A/B 无缝交替试听（Toggle A/B）**：
   - 点击「⇄ 交替听 A / B」时，若 A 正在播放，则记录当前播放时间戳，瞬间暂停 A 并从相同时间戳（或头部）启动 B 播放；反之亦然；
   - 让用户在几秒钟内快速对比相同和弦或旋律小节的音色饱满度与节奏稳定性。

## 4. 数据模型与工程架构 (Data Models & Architecture)

### 4.1 数据模型（SwiftData 映射）

在现有 `Project` 与 `PracticeItem` 架构下扩展，不引入破坏性迁移：

```swift
// Project 扩展属性（基于原有模型）
extension Project {
    // 项目名称
    // var name: String
    
    // 完成标准与目标描述 (UI呈现为目标)
    // var goal: String?
    
    // 当前训练重点与指引 (用于「下次练什么」)
    // var nextPracticeFocus: String?       // 如 "收尾节奏稳定"
    // var nextPracticeInstruction: String? // 如 "先练收尾，再连弹整段副歌。"
    
    // 显式认定的阶段基准版本练习 ID
    // var milestoneVersionItemId: UUID?
    
    // 最终作品版本练习 ID
    // var finalVersionItemId: UUID?
}

// 练习项目 ProjectItemSnapshot 结构保持纯粹
struct ProjectMilestoneNode: Identifiable, Sendable {
    let id: UUID
    let date: Date
    let label: String       // 如 "分段练副歌"、"连贯弹唱"、"完整弹唱一遍"
    let practiceItemId: UUID
    let isCurrent: Bool
}
```

### 4.2 进步轨迹（Progress Story）里程碑自动推导算法

为实现“规则推导 + 非完成度评分”，系统按以下规则从关联练习项中提取 3 个代表性节点：
1. **时间跨度筛选**：取该项目首个有效练习日、中位进展日与最近一次有效练习日；
2. **范围关键词提取（Heuristic Extraction）**：
   - 若练习标题/内容包含「单句 / 小节 / 分段 / 副歌专项 / 慢练」，归类为阶段 1「分段练习」；
   - 若包含「串联 / 连贯 / 变速 / 进阶」，归类为阶段 2「连贯串联」；
   - 若包含「完整 / 整首 / 跟唱摸底 / 录音对比」，归类为阶段 3「完整演奏」；
3. **兜底展示**：若历史练习少于 3 条，按实际练习数展示 1~2 个节点，虚位展示后续预期演进。

## 5. 用户故事与验收标准 (User Stories & Acceptance Criteria)

### 5.1 用户故事

1. **US-1 (看见演进历程)**：作为一个吉他自学者，我希望进入项目详情能立刻看到我的练习是如何从局部小节演进到整首演奏的，而不是一个枯燥的百分比数字，从而获得成就感。
2. **US-2 (快速回听上次成果)**：作为一个正在攻克难曲的用户，我希望在项目详情页就能一键试听上次练习的录音片段，不需要翻找深层录音文件。
3. **US-3 (A/B 录音变化对比)**：作为一个练习了一段时间的用户，我希望能将最近的录音和最初/阶段录音并排交替播放，听出自己在和弦转换处停顿的减少。
4. **US-4 (AI 关键停顿观察)**：作为对节奏不敏感的用户，我希望在录音对比中看到关键秒数（如 00:38 处）的连贯性提示，帮助我印证自己的耳朵。
5. **US-5 (无缝发起今日练习)**：作为一个打开 App 准备练琴的用户，我希望在项目详情页看完进步后，点击“下次练什么”就能直接进入今天这一项的练习，标题和重点自动带过去。
6. **US-6 (集中回顾所有项目笔记)**：作为一个喜欢写练习心得的用户，我希望在一个列表里倒序回顾每次练习记下的体会，并能随时跳转回原记录查看或修改。

### 5.2 验收标准 (Acceptance Criteria)

- [ ] **AC-1 (UI 与 Figma 1983:2 严格对齐)**：
  - 项目详情主屏包含且仅包含：项目名称+目标、Progress Story 卡片、Last Practice 卡片、Next Practice 卡片、My Notes 前 3 条预览；
  - 移除原先冗余的阶段/类型未设置卡片与无用按钮。
- [ ] **AC-2 (Progress Story 里程碑展示)**：
  - 里程碑展示不包含任何诸如“完成度 %”的数字；
  - 标注展示「根据已记录的练习范围 · 非完成度评分」；
  - 至少支持渲染 1~3 个时间轴节点，高亮末尾最新节点。
- [ ] **AC-3 (上次练习与波形播放器)**：
  - 上次有效练习有录音时，展示 22 柱波形条与试听键；
  - 点击试听正常发声，波形柱产生高亮进度；
  - 点击「与阶段版对照 ›」正常 push 打开 **录音对比页 (Screen 02)**。
- [ ] **AC-4 (录音对比页双轨与 A/B 交替)**：
  - 阶段版（A）与最近录音（B）独立展示时长与录音时间；
  - 点击任一播放器，另一播放器自动暂停；
  - 点击「⇄ 交替听 A / B」，正在播放的音轨无缝切换至另一方；
  - 点击右上角「更换录音」，弹出 Sheet 允许重新指定对比项目。
- [ ] **AC-5 (AI 观察与笔记引用)**：
  - 观察卡片展示两段录音的结论与带有具体时间戳的对比点；
  - 离线无网络时，优雅呈现基于用户历史笔记的要点对比；
  - 笔记引用区域展示对比引用的 2 条笔记。
- [ ] **AC-6 (State Handoff 状态流转)**：
  - 当天首次从「下次练什么」进入：生成 1 条今天的新练习项，预填重点，关联该项目；
  - 当天已有未完成练习再次点击：直接定位并打开该练习，不增加重复记录；
  - 当天已完成练习后点击：提示已完成并创建新的练习项。
- [ ] **AC-7 (我的笔记历史与只读真理源)**：
  - 点击「查看全部 ›」打开项目笔记历史列表；
  - 列表展示所有关联练习的笔记，带录音角标；
  - 点击任一条目的「查看练习记录 ›」跳转至该练习的 `PracticeDetailView`；
  - 底部包含「笔记来自每次练习，可在原练习记录中修改」提示。

## 6. 异常场景与边界处理 (Edge Cases)

| 场景 | 表现与处理策略 |
|---|---|
| **冷启动项目（0 条练习记录）** | Progress Story 展示虚位引导（如“完成第一次练习以生成轨迹”）；上次练习与笔记模块展示友好占位文案；主行动卡片展示「开始第一次练习」。 |
| **仅有 1 条有效录音** | 上次练习卡片正常展示该录音；右侧对照入口文案变为灰度提示或置灰说明「再记录一次录音即可开启对照」。 |
| **有练习记录但无录音** | 上次练习卡片正常展示时长、练习内容与反思笔记，隐藏音频播放条；对照入口不激活。 |
| **有练习记录但未填写笔记** | 笔记预览区域展示默认占位文案（如“本次练习未记录文字心得”），不破坏列表高度。 |
| **关联练习被用户删除** | 项目详情页重新计算关联 items，自动剔除 `deletedAt != nil` 的记录，时间轴与上次证据动态平滑重算。 |
| **离线环境使用录音对比** | 本地音频播放完全离线可用；AI 观察卡片自动降级为展示本地笔记比对与规则特征摘要，网络恢复后再进行增强。 |
