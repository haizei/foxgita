# Gita 项目初始化视觉对齐设计

> 日期：2026-08-29  
> 状态：已确认，待写实现计划  
> 产品依据：[项目初始化视觉对齐 PRD](./2026-08-29-project-init-visual-prd.md)  
> 视觉依据：[Figma · Flow / Project Initialization](https://www.figma.com/design/smeuuUaTOYE1URHhIGbzyd/%E5%90%89%E4%BB%96%E8%AE%AD%E8%AE%B0app?node-id=624-405)  
> 前置：[项目初始化流程设计](../../../../../docs/superpowers/specs/2026-08-29-project-init-flow-design.md)  
> 范围：空状态、创建/编辑、Ready 三屏按 Figma 验收；类型/阶段写回项目。不改 Schema、不做按类型切换的阶段模板。

本文修订初始化流程设计中「创建/编辑不展示类型阶段、保存写成空」的条款。路由、Ready 只从空状态进入、放弃确认、长度上限、埋点漏斗仍按原文，除非本文写明覆盖。

## 1. 背景与目标

初始化流程已经上线：空状态能创建，成功后进 Ready。按 Figma 做的第一轮视觉里，创建页把主按钮钉在滚动区外。键盘弹起后中间只剩一条缝，「完成目标」和「当前重点」重叠，提示被挤没；示例文案当占位时看起来像已填，未启用的主按钮浅到看不清。上一份设计还要求保存时清空类型/阶段，和 Figma Goal + Focus、Ready 上的阶段徽章矛盾。

本期把三屏收到 Figma Project Initialization 的验收标准上，并把类型、阶段作为选填写入项目。创建仍只要求名称和完成目标。

成功标准：键盘弹起时字段不重叠、当前输入和主按钮仍可见可点；未填时占位不像已填、主按钮仍可读；有值的类型/阶段能保存，并在 Ready、列表该出现的地方出现。

## 2. 范围

### 做

- 空状态、创建/编辑、Ready 按 Figma 对应画板验收。
- 创建/编辑补回类型芯片和当前阶段；写入 `kindRaw` / `stageRaw`。
- 键盘弹起时的可滚与主按钮位置，避免字段重叠。
- 占位与未启用主按钮的对比度。
- Ready：阶段非空才画徽章；重点规则不变。
- 覆盖「保存时把类型/阶段写成空」。

### 不做

- 改 SwiftData Schema。
- 按项目类型切换不同阶段列表。
- 阶段自由输入（五档之外的旧自由文本：见 4.3）。
- Ready 上展示类型芯片。
- 把 Figma 示例曲目预填进字段。
- 增加返回箭头（仍只关闭 / ×）。
- 改路由：Ready 仍只从 `fromEmpty: true` 进入。
- 封面、截止日期、频率、任务清单、AI、云同步。

## 3. 三屏

视觉：`GitaTheme`、`GitaFont`、`PageBackground`。不新增色值。对照节点：

| 屏 | Figma 画板 |
|---|---|
| 空状态 | Gita / Record Projects / Empty |
| 创建/编辑 | Gita / Project Setup / Goal + Focus |
| Ready | Gita / Project Setup / Ready |

### 3.1 空状态

无未删除项目时，项目分段是白卡片，不是灰底短文案。

必须出现：

- 色标「跨天目标」
- 标题「把多天练习连成一个项目」
- 说明：项目记录完成目标和当前重点；练习时间、笔记与媒体仍在每天的练习项里
- 三条收益：看见上次练到哪里；保存下一次的唯一重点；从项目直接创建今天的练习
- 全宽胶囊「创建第一个项目」→ `projectCreate(fromEmpty: true)`
- 「暂不创建，继续自由练习」→ `recordSegment = .practice`，不写 Project
- 脚注：创建项目不会改变已有练习，也不会要求所有练习都归入项目

保留记录标题、数据统计、「练习 / 项目」分段。无强制弹窗。有未删除项目时不展示这套空状态；列表头「创建项目」仍 `fromEmpty: false`。

### 3.2 创建 / 编辑

同一 `ProjectEditorView`。标题创建为「创建项目」，编辑为「编辑项目」。只有关闭（×），不要返回箭头。脏检查与放弃确认沿用初始化流程，并把类型、阶段算进脏。

#### 字段

| 顺序 | 控件 | 必填 | 写入 |
|---|---|---|---|
| 1 | 项目名称 | 是 | trim 后 1–40 |
| 2 | 完成目标 | 是 | trim 后 1–120 |
| 3 | 类型芯片：歌曲 / 技巧 / 演出准备 | 否，单选；再点已选项则取消 | `kindRaw` 存中文芯片文案；未选 `""` |
| 4 | 当前阶段 | 否 | `stageRaw` 存中文选项文案；未选 `""` |
| 5 | 当前重点 | 否 | trim 后最多 120；空则 `""` |

选填区标题「补充练习方向」，右侧「选填」。重点旁注：「写下一次练习最值得关注的一件事，不是待办。」

必填/选填要标明。不出现截止日期、频率、总时长、次数、任务、进度百分比。

主按钮：创建为「创建项目」，编辑为「保存」。两个必填 trim 后都非空才可点。类型、阶段、重点不阻塞提交。第一次进入不报错；提交或离开字段后再校验。错误在对应字段旁，其他内容不清空。超长直接截断。

#### 占位与强调底

Figma 上的「学会《知足》」「跟着原唱，稳定完成整首弹唱」「主歌进入副歌时保持节奏」只做占位，不是预填，也不写入。未输入时用次要色，不能做成已填正文色。

浅橙底只表示目标、重点这类强调框，不表示已填。名称用白底描边。

未启用的主按钮保持品牌橙和白字，用降低不透明度表示不可点；不得浅到看不清「创建项目」。启用后为稿上的实心胶囊。

#### 键盘与主按钮

键盘收起：主按钮贴在内容底部，全宽胶囊，与稿一致。

键盘弹起：

- 可滚区域不被压成一条缝
- 当前焦点字段完整可见
- 主按钮在键盘上方，不和「当前重点」或其他输入重叠
- 当前字段和主按钮都能滚到或始终可见

#### 阶段选择

点「当前阶段」行，打开系统选择列表。选项固定、所有类型共用：

1. 不选择
2. 熟悉内容
3. 分段练习
4. 串联整首
5. 稳定演奏
6. 完成

选完回到表单。行左「当前阶段」，右为所选文案和 ›；未选时右侧表示未选择，不要编造「串联整首」。

### 3.3 Ready

仅 `fromEmpty: true` 创建成功后出现。读已保存 Project，不沿用表单草稿。

必须展示：成功对勾、「长期目标已经有了方向」、「接下来从一次真实练习开始」、项目名称、完成目标（标签「完成目标」+ 原文）。

阶段：`stageRaw` trim 后非空才在名称右侧画徽章，文案用存储值对应的中文；空则整颗徽章不画。

重点：trim 后非空才画「第一次练什么」块（重点原文 +「会作为今天练习项的初始关注点」）；空则整块不画。

不展示类型芯片。不进入编辑。

顶部「完成」与「先返回项目列表」同义：都是 pop，不确认。主操作「创建今天的练习项」：成功后用练习详情替换 Ready；失败留在 Ready，项目已在，可再点。提交中锁定主按钮。

## 4. 数据

不改 Schema。`kindRaw` / `stageRaw` 仍是已有字符串。

### 4.1 类型

`kindRaw` 直接存芯片中文：`歌曲` / `技巧` / `演出准备`。未选为 `""`。本期不在 Ready 展示类型；列表、详情若本来不画类型，不强加。

### 4.2 阶段

`stageRaw` 直接存选项中文：`熟悉内容` / `分段练习` / `串联整首` / `稳定演奏` / `完成`。未选为 `""`。

Ready、当前项目卡、项目详情已有的阶段展示继续读 `stageRaw` 原文。受控值和旧自由文本都按「非空就显示原文」，不必再做英文键映射。

### 4.3 旧自由文本

编辑打开时，若 `stageRaw` 或 `kindRaw` 不是上表受控值：

- 行上显示原文（或无法映射的类型不选中任何芯片）
- 不在打开时自动改写
- 用户选了受控项再保存，才换成新值
- 用户未改阶段/类型就保存：原值保持，不清成空

`createProject` / `updateProject` 按调用方传入的 kind/stage 写入，不再由编辑页无条件传 `""`。

## 5. 异常

| 情况 | 表现 |
|---|---|
| 必填为空或仅空白 | 不提交；字段旁提示 |
| 只填了类型/阶段/重点 | 仍不可提交 |
| 创建/保存失败 | 留在表单，输入保留，可再点 |
| 创建中连点 | 忽略；只一条 Project |
| 键盘弹起 | 字段不重叠；主按钮不贴进输入框 |
| 占位可见、字段为空 | 主按钮不可点，但文案可读 |
| Ready 创建练习失败 | 项目已在；留在 Ready；可再点 |
| 放弃关闭 | 库中无新项目、无新练习项 |

离线：本地保存成功即成功。保存失败不得把页面换成 Ready。

## 6. 埋点

沿用初始化漏斗。不上传类型、阶段、名称、目标、重点原文。不强制新增 `has_kind` / `has_stage`。

## 7. 验收

- 无未删除项目：空状态白卡片含色标、三条收益、全宽主按钮、次操作、脚注。
- 名称、目标未填：主按钮不可点且「创建项目」可读；占位不是正文色，也不被当成已填。
- 只填名称和目标可创建；类型、阶段、重点留空不阻塞。
- 选了类型和/或阶段：保存后库中为对应受控值；Ready 有阶段才画徽章。
- 键盘弹起：目标与重点不重叠；焦点字段完整；主按钮在键盘上方。
- 空状态创建成功进 Ready；列表创建、编辑、新建并加入不进 Ready。
- Ready 没填重点不画重点块；没填阶段不画徽章。
- 编辑保存不再把已有类型/阶段清成空。
- 旧自由文本阶段在未改选时保持原文。
- 创建项目不产生 PracticeItem。Ready 创建今天练习的规则沿用初始化流程设计。

不测：按类型切换的阶段模板、封面、云同步、跨会话草稿。

## 8. 实现备注

实现写在 `foxgita/`。主要改动面：`ProjectEditorView`（布局、芯片、阶段选择、占位、主按钮）、`ProjectReadyView`（阶段徽章）、`RecordView` 空状态（若与稿有缺口）、`ProjectSetupRules` / 编辑保存传入的 `kindRaw` / `stageRaw`。不要为类型阶段改 Schema。阶段选择用系统列表，不新开设计稿上没有的自定义全屏。
