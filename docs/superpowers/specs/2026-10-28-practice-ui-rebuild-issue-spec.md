## Problem Statement

Gita 的练习者希望在同一条练习中连续完成跟拍、计时、写笔记、录音录像和回看。新版设计已经覆盖这些任务，但当前应用仍使用旧声音面板、互斥视觉模式和固定录音波形，练习计时还依赖节拍器启动，单独录音可能留下零时长记录。

用户已经反馈音色“太难听”，要求调整颜色、字体、白底与可复用面板，并明确指出过 MT-04“这个没变啊”。只更新设计或替换局部音色列表，不能解决实际界面、音频、状态和保存规则不一致的问题；返回、暂停、到零和完成的区别必须可信，练习内容不能因失败丢失或重复统计。

## Solution

基于 Figma「练习页面相关 · 笔记 / 节拍器 / 倒计时」完整改造原生 iOS 练习详情，连同真实功能、本地领域服务、音频、文件与持久化一起交付。用户可以在一个上下文中调节节奏与七种音色、组合视觉反馈、独立计时、进行变速或限时练习、记录与回看内容。

主内容按节拍器、计时、步骤、笔记与媒体、完成排列。主卡齿轮进入完整白底音效与视觉设置；视觉偏好全局保存，节拍与声音随每条练习保存。Practice Elapsed Time 独立于节拍器，主暂停联动计时、倒计时、播放和录音；返回保存未完成内容，明确完成才改变练习完成状态。

本规格承接用户两轮全部采纳的 Q1–Q13，不再引入项目继承、步骤覆盖、三种环境声音模式或云后端。应用保留系统字体与 Gita 视觉语言，保留现有七音色、TAP、变速训练、四态重音、八种细分、后台连续和历史数据兼容。

## User Stories

1. 作为进入练习详情的吉他练习者，我希望先看到节拍器和计时，再看到步骤与笔记，以便按实际练习顺序使用工具。
2. 作为需要调整声音的练习者，我希望从主卡的明确入口进入设置，以便不必猜测隐藏操作。
3. 作为打开设置的练习者，我希望看到完整的音效、音色和视觉面板，以便所有相关控制都有清楚的归属。
4. 作为使用设置的练习者，我希望通过明确关闭或下滑收起回到练习，以便不中断当前上下文。
5. 作为无声练习的用户，我希望关闭节拍器仍能累计实际时长，以便练习记录不依赖音频启动。
6. 作为开始练习的用户，我希望音频启动失败时得到提示并保留已发生的时长，以便故障不会抹掉练习。
7. 作为暂停练习的用户，我希望实际计时、已启用倒计时、节拍器和录音一起暂停，以便停止练习时不继续累计或采集。
8. 作为继续练习的用户，我希望恢复此前启用的工具，以便不被擅自打开节拍器或录音。
9. 作为只暂停录音的用户，我希望实际计时和节拍器继续，以便暂停采集而不停止练习。
10. 作为曾自行暂停录音的用户，我希望主暂停后继续时录音仍保持暂停，以便我的采集选择得到保留。
11. 作为停止录音的用户，我希望当前片段保存而练习继续，以便分段录音不等同结束练习。
12. 作为返回列表的用户，我希望笔记、附件和时长保留且练习仍未完成，以便稍后继续。
13. 作为明确结束练习的用户，我希望顶部和底部完成入口执行相同动作，以便不用理解两套结束规则。
14. 作为保存失败的用户，我希望练习不会显示完成且草稿仍在，以便修复或重试后继续。
15. 作为限时练习的用户，我希望选择 1–60 分钟及 5/10/15 分钟快捷值，以便快速安排练习时段。
16. 作为调整倒计时的用户，我希望“完成”只保存计划，以便设置不会突然启动播放。
17. 作为准备开始限时练习的用户，我希望明确点击“开始倒计时”才运行，以便掌握开始时机。
18. 作为暂停倒计时的用户，我希望剩余时间保持、继续后接着倒数，以便暂停时间不计入练习。
19. 作为重设倒计时的用户，我希望从新总时长等待启动且不清零已练时长，以便调整目标不改写实际记录。
20. 作为倒计时到零的用户，我希望停止运行并保存录音而不自动完成练习，以便决定是否继续或补充笔记。
21. 作为不使用节拍器的限时练习者，我希望倒计时仍然可用，以便安静练习也能控制时间。
22. 作为离开后重进练习的用户，我希望临时倒计时不会自行恢复，以便不误以为上次计时仍在运行。
23. 作为未授予提醒权限的用户，我希望知道提醒未启用且仍能倒计时，以便权限不阻断练习。
24. 作为选择音色的用户，我希望保留七个熟悉的预设名称，以便现有记录和选择仍能理解。
25. 作为使用编号选择音色的用户，我希望编号 1–7 与卡片同步，以便始终知道当前唯一选择。
26. 作为使用音色加减按钮的用户，我希望到两端停止，以便不会意外跳回另一端。
27. 作为尚未正式播放的用户，我希望选择音色时试听当前配置的两小节，以便比较实际节奏中的听感。
28. 作为反复比较音色的用户，我希望耳机按钮重复试听且不叠加声音，以便做清楚的比较。
29. 作为只试听的用户，我希望试听不启动练习时长、倒计时或训练记录，以便记录只反映正式练习。
30. 作为播放中切换音色的用户，我希望下一次发声使用新音色且节拍连续，以便不用重新开始跟拍。
31. 作为播放中使用耳机按钮的用户，我希望不会插入第二路试听，以便不被额外拍点干扰。
32. 作为调音量的用户，我希望看到 0–100% 且切换音色不移动音量，以便控制自己的发声水平。
33. 作为临时需要安静的用户，我希望静音只关闭声音、保留原音量和拍点，以便取消静音后立即恢复。
34. 作为需要强调强拍的用户，我希望独立控制强拍增强，以便增强关闭后不会被其他选项重新打开。
35. 作为使用辅助提示的用户，我希望振动与闪拍各自可控，以便音色切换不暗中改变它们。
36. 作为从设置进入录音的用户，我希望使用当前练习的同一个录音状态，以便不会产生平行录音会话。
37. 作为需要远距离看拍点的用户，我希望进入大屏节拍器并返回原练习，以便共享同一节奏、计数和控制状态。
38. 作为调整拍号的用户，我希望分子和分母都有明确边界，以便不会保存不受支持的拍号。
39. 作为使用 6/8 拍的用户，我希望 BPM 明确按八分音符计拍，以便 120 BPM 表示每秒两个主拍而非隐含换算。
40. 作为编辑重音的用户，我希望保留强、次强、普通、静音四态，以便表达需要的拍级。
41. 作为选择细分的用户，我希望保留八种已定义细分，以便既有练习方式仍可用。
42. 作为播放中调整节奏的用户，我希望拍号、重音和细分在下一小节一起应用，以便不中途拼接不一致配置。
43. 作为调整速度的用户，我希望保留调速、TAP 与已有速度范围，以便新界面不缩减能力。
44. 作为变速训练者，我希望设置起始/目标速度、阶段小节数、步长和预备小节，以便按计划训练。
45. 作为暂停或被打断的训练者，我希望训练进度与结果保持准确，以便最高稳定速度和完成原因仍可信。
46. 作为依赖视觉跟拍的用户，我希望节拍模块与钟摆能同时开启，以便组合适合自己的提示。
47. 作为暂不需要视觉的用户，我希望能关闭两个视觉模块而保持声音与计时，以便减少干扰。
48. 作为筛选高亮的用户，我希望强、次强、普通勾选只改变视觉高亮，以便不会误改发声或力度。
49. 作为查看静态节奏的用户，我希望取消高亮仍保留重音图案，以便知道配置本身没有改变。
50. 作为查看小节的用户，我希望显示“第 N 小节”且从正式第一小节起算，以便预备阶段不混入实际练习计数。
51. 作为暂停后继续的用户，我希望小节序号保留，重置或新一轮才从 1 开始，以便知道训练的实际位置。
52. 作为切换练习的用户，我希望视觉偏好通用而节拍和声音各自保存，以便既不用反复设置显示也不串用节奏。
53. 作为写笔记的用户，我希望最后一次输入短延迟后自动保存，以便专注记录而非频繁点保存。
54. 作为写完马上返回或退后台的用户，我希望最新内容立即提交，以便不依赖防抖等待。
55. 作为查看保存状态的用户，我希望区分保存中、已保存和失败，以便不会把未保存内容当作已落盘。
56. 作为连续修改笔记的用户，我希望旧保存回调不覆盖新草稿，以便慢保存不会回退内容。
57. 作为语音写笔记的用户，我希望设备端转文字插入当前光标并继续编辑，以便不替换整篇笔记或额外保存原始语音。
58. 作为开始语音输入的用户，我希望练习暂停且当前录音先保存，以便语音输入与练习采集不混淆。
59. 作为录音中的用户，我希望波形反映真实麦克风输入，以便知道采集确实在进行。
60. 作为暂停或停止录音的用户，我希望波形分别冻结或清除活动状态，以便视觉反馈与录音一致。
61. 作为使用录像的用户，我希望实际计时继续、节拍器暂停并在返回后由我恢复声音，以便录像期间的规则可预测。
62. 作为录像中遇到倒计时到零的用户，我希望练习时长截至零点但视频仍可保存，以便截止不会导致媒体丢失。
63. 作为取消录像的用户，我希望不生成空附件且不回滚已发生的练习时间，以便记录符合实际行为。
64. 作为添加练习图片的用户，我希望从相册或拍照加入本条记录，以便把资料与笔记一起回看。
65. 作为已有三张图片的用户，我希望被明确告知数量上限，以便不会误以为第四张已保存。
66. 作为从文件导入资料的用户，我希望支持可读取的图片、音频和视频，以便不用在应用外维护对应关系。
67. 作为回看练习的用户，我希望播放录音或视频附件，以便复盘真实练习过程。
68. 作为取消导入或选到损坏文件的用户，我希望原记录保持不变且错误可恢复，以便不会留下假附件。
69. 作为媒体保存失败的用户，我希望文件仍可重试且只清理本次失败新增内容，以便不删除已有记录。
70. 作为拒绝麦克风、相机或照片权限的用户，我希望看到明确状态并继续使用其他工具，以便单项权限不锁住整页。
71. 作为从项目回看笔记的用户，我希望修改原练习唯一笔记后投影列表同步变化，以便没有第二份可写副本。
72. 作为查看历史练习的用户，我希望允许编辑的内容与受限的时长、采集和完成权限区分，以便旧事实不会被意外改写。
73. 作为升级应用的用户，我希望旧记录、声音选择和媒体关系仍可读取，以便改造不要求丢弃历史数据。
74. 作为查看方案汇总的用户，我希望只累计实际练习明细，以便不会再加上倒计时、视频长度或一份汇总时长。
75. 作为锁屏或切到后台的练习者，我希望既有播放和录音连续规则保持，以便正常练习不因屏幕状态停止。
76. 作为遇到来电、耳机丢失或音频服务重置的用户，我希望保存当前录音并暂停、由我手动恢复，以便不突然外放或自动续播。
77. 作为使用窄屏或大字号的用户，我希望长内容能滚动且文字与操作不裁切，以便所有功能仍可达。
78. 作为 VoiceOver 或减少动态效果用户，我希望按钮、选中状态和静态拍点可理解，以便不被逐拍播报或强制动画干扰。
79. 作为比较新版声音的练习者，我希望先听同条件木质、电子与强拍对照，以便选择可接受且能辨认拍点的素材。
80. 作为长期使用节拍器的用户，我希望声音无削波、切换无漏拍且连续运行稳定，以便改善音质不会牺牲跟拍能力。

## Implementation Decisions

1. **平台与本地后端边界**：使用现有 SwiftUI、Observation、SwiftData 与 AVFoundation，最低 iOS 18，当前 schema V19。本轮“后端”指本地领域服务、音频引擎、文件及持久化，不建立练习 CRUD 云 API、账户或同步服务。
2. **职责划分**：练习详情组合各工具；增加统一运行协调，承接开始、暂停、继续、录像展示、到零、返回和完成。PracticeStore 继续作为写入命令边界；PracticeTimer、PracticeCountdown、MetronomeEngine、TempoController、录音/录像服务继续复用。统一笔记保存器处理防抖、版本与 flush，导入器处理文件所有权；不建立第二个音频引擎或第二份时长事实。
3. **保存归属**：每条 PracticeItem 保存 BPM、拍号、细分、重音、音色、音量及强拍增强。Metronome Visual Preferences 为全局偏好，含节拍模块、钟摆、三级高亮、小节计数显示；振动和闪拍作为独立全局设备反馈偏好。临时静音、全屏和倒计时均属于本次访问；倒计时离开后取消。不引入项目默认或步骤覆盖继承。
4. **兼容与默认**：全局偏好使用带版本的本地偏好存储，缺失或坏值回退默认，不影响练习。默认节拍模块开、钟摆关、三级高亮全开、小节计数关、振动沿当前默认开、闪拍关；保留现有声音配置默认真实节拍器、音量80、强拍增强开。旧 BeatTrackMode 未持久化，不虚构迁移来源。现有字段足够时保持 V19，不编辑已发布 schema；确需新字段先补正式迁移与旧库验证。
5. **布局与入口**：详情顺序为节拍器、计时卡、步骤、笔记/媒体、完成。主卡保留拍号/速度/细分三列，右上齿轮打开完整 MT-04；拍号/细分进节奏设置，速度进调速/TAP/变速设置。面板支持明确关闭和下滑；顶部录音复用当前录音命令，展开进入共享同一运行状态的大屏。装饰螺丝不可操作，长画板不等于固定屏幕高度。
6. **完整 MT-04 与视觉资源**：按完整新版音效、音色和视觉面板实现，不能退回旧紧凑七卡片列表。白底 #FFFFFF，主橙 #FF7925、正文 #292929、次级 #999999、浅底 #F6F6F6、边框 #D6D9DE，复用 Gita 语义颜色。字体用 Gita 系统字体与 Dynamic Type；Figma Noto Sans SC 是预览字体。现有生成的圆形底座/小节开关图片可用作外观，文本和交互仍为原生控件；只改变指定面板，不改写全局主题。
7. **实际计时独立**：Practice Elapsed Time 不依赖引擎启动成功。主开始/继续运行实际计时及已启用倒计时，节拍器按当前启用意图恢复；直接关闭节拍器与临时静音是不同状态。音频失败提示错误，不抹除已发生的时长。静默练习不靠循环无声播放器保活，返回前台按时钟补算。
8. **暂停与录音原因**：主暂停同时暂停实际计时、倒计时、节拍器、训练和正在采集的录音。区分主暂停与录音自行暂停；主继续只自动恢复由主暂停暂停的录音。录音自身暂停不停止计时/节拍器，录音自身继续时先确保实际计时运行。停止录音保存一个附件，但不结束练习。开始录音只有权限通过且实际采集成功后才启动/继续练习计时。
9. **录像和展示生命周期**：复用系统相机，成功展示后实际计时开始/继续，节拍器暂停，现有音频片段先保存；退出后不自动开声。设置、全屏、相机和文件选择器是练习子界面，不被通用消失事件误当成离开。相机取消不创建空附件、不回滚已练时长；倒计时到零时实际累计截至零点，允许视频继续完成保存，视频时长可长于有效练习时长，不能按元数据再加一遍。
10. **返回与完成**：返回保存未完成内容并停止本次运行、取消临时倒计时。上下完成入口使用同一命令，先保存当前笔记与媒体并停止运行，提交成功才标完成；失败保留草稿、pending 文件及重试入口。沿用现有有效练习判断和空记录处理，不为了保存设置制造实际时长。
11. **倒计时契约**：1–60 分钟，首次取当前练习目标，无目标默认10分钟，提供5/10/15快捷值。“完成”保存新的暂停计划，不启动；“开始倒计时”才运行。调整从新总时长等待启动，复位不清零 Practice Elapsed Time。无节拍器也能倒计时；音频截止与时钟完成合并为一次 Countdown Completion，到零停止播放、暂停时长、保存结束录音并按提醒选择反馈，但不等于 Practice Completion。保留与变速训练互斥及原有前后台提醒，通知权限不可用显示未启用而不阻断开始。
12. **拍号与 Beat Unit**：分子保留2–12，分母按2/4/8/16步进且两端停止。BPM 表示当前分母音符每分钟拍数；6/8、120 BPM 为每秒两个八分音符主拍，不自动转附点四分音符。细分相对当前主拍，不因分母重复缩放。旧非标准正整数分母读取显示按4规范化，下次用户保存才写回，不批量改旧库。
13. **节奏变更与训练**：保留四态 Accent Pattern、八种细分、整体40–200 BPM，调速刻度可见40–160。拍号/重音/细分沿下一小节边界原子应用，UI 区分待应用与已应用。TAP 与变速按现有边界语义；保留起始/目标、阶段小节、步长、预备小节、Target Hold、暂停/中断历史及训练持久化。
14. **视觉与 Bar Counter**：节拍模块和 Pendulum Feedback 可共存或全关。Beat Highlight Filter 的强/次强/普通只影响运行高亮，保留静态图案，不修改声音、力度或时间线。小节显示主卡“第 N 小节”，正式第一小节为1、预备排除；暂停继续保留，重置或新一轮从1开始，嵌入与全屏共享计数。必须消费真实音频时间线事件，不能用屏幕刷新或已练分钟推算。
15. **七音色与编号**：顺序固定为真实节拍器、电子节拍器、风铃声、木鱼声、架子鼓1、架子鼓2、拍手，保留现有 rawValue 和旧值解码。编号1–7与卡片共享单一选中状态，±到端点停止。未正式播放时选择并试听两小节，耳机可重复，旧试听先结束；试听不污染练习时长、倒计时、正式小节与训练历史。
16. **运行时热切换与静音**：正式播放中切换音色从下一次发声生效，不重启 BPM/相位/小节，不插入额外试听；耳机不叠加第二播放。验证必须覆盖已排队音频缓冲，不能仅验证预设属性变化。音量0–100，切换不修改音量。Temporary Metronome Mute 关闭音频输出但保留拍点、原音量及计时，取消后恢复；不把静音写成音量0。
17. **独立辅助提示**：“更多声音设置”承接强拍增强、振动、闪拍。强拍增强只改音频辨认，不改变节奏；反馈开关独立于预设，移除拍手自动闪拍行为。反馈继续由同一时间线驱动，后台不进行前台高亮动画或逐拍反馈，不使用独立 UI 定时器制造拍点。
18. **音色调音**：本轮包含素材改善，先提供同设备、同系统音量、同节奏的木质、干净电子、强拍 A/B，由需求方选定后再更新正式资源；候选产出不等于批准。保留七名和普通/强拍14份素材、可追溯许可、预加载及现有约70ms契约；音频格式沿现有44.1kHz、单声道、16-bit PCM及峰值余量检查。优先减少当前过度饱和和过度降速造成的问题，不以隐藏增益、强制路由或音频回调读文件换效果。若改变素材契约须明确理由并验证快速细分。
19. **Practice Note 自动保存**：每条练习一份文本笔记，最后输入600ms后保存；退后台、返回、完成 flush 最新版本。异步任务以版本和顺序防止旧回调覆盖新草稿；只有成功才显示已保存，失败保留草稿并可重试。自动保存不等同完成。历史内容编辑仍遵循原入口权限，不能越权改累计时长、采集或完成。
20. **语音输入与真实波形**：设备端语音识别插入当前光标，不替换整篇笔记、不保留原语音为附件；开始时暂停练习并结束保存当前录音，结束后用户手动恢复。录音波形读取真实麦克风电平，显示平滑短窗口；暂停冻结、停止清除活动状态，不用固定图案模拟输入，不为波形启用独立环境监听。
21. **图片与媒体导入**：照片/拍照/文件均归属本次 PracticeItem，图片合计最多三张，沿现有压缩和本地文件管理。文件导入支持系统可读图片、音频和视频，先私有复制和元数据验证，再由 PracticeStore 保存关系；平衡系统文件访问授权，期间显示进度并防重复。取消或失败只补偿本次新增文件，现有附件不动；数据库成功后才 detach pending。拒绝不支持、无法解码或损坏文件，权限拒绝/无相机/磁盘失败可恢复，不显示假成功。不额外人为减少已支持的音视频附件数量。
22. **历史与投影**：Project Note Projection 从原练习的唯一 note 读取，修改/清空后项目列表和详情响应更新，不增加项目可写笔记。历史入口保留原权限，可查看、允许编辑或继续的范围沿现有规则；不会因为自动保存绕过限制。方案汇总只读实际明细，不把倒计时、媒体长度或第二份 Session 时长再次加总，跨天与入口行为不被本次界面重排改写。
23. **中断与可访问性**：保留 Playback Continuity、Recording Continuity 和音频截止约束，锁屏/后台正常连续；来电、Output Route Loss、Audio Service Reset 保存结束当前录音并暂停，事件结束后必须手动恢复，耳机断开不悄悄外放，会话失败回滚占用。控件命中至少44pt，大字号/窄屏可换行和滚动；VoiceOver 读名称与状态，不逐拍抢读，减少动态效果时用静态拍点。指定白底面板在深色系统外观下仍清楚，不强迫全应用变白。
24. **范围与交付阶段**：按运行/保存基础、十场景联通、音色定稿、集成验收推进，候选音色可并行。阶段构建不等于已完成整轮。所有已确认功能均为本次交付范围，不能自行降级后续；用户未给硬期限，不虚构上线日期。现有未提交工作是集成基线，不重置、不整文件覆盖他人修改。工程允许选择实现细节，但不新增本规格外产品能力。

## Testing Decisions

1. **唯一主验收 seam 为现有练习详情完整端到端流程**：创建或继续 PracticeItem → 打开设置并改节奏/音色/视觉 → 静默或发声计时 → 录音/录像及暂停 → 笔记与附件保存 → 返回重进或完成。用户已明确确认“符合，按此写入规格”。复用现有 PracticeFlowUITests 的真实入口、UI 测试启动数据和可访问性标识；不是为每个新视图搭一个独立主 seam。
2. **好测试验证外部行为**：从用户操作观察显示、实际存储结果、媒体关系、可恢复状态及播放事件时间。避免检查私有属性、子视图树、固定帧数或照抄实现。截图/几何检查只验证设计结构，不能证明声音质量。变更旧模式断言时依据本规格更新，同时保留无关回归；不把“没有崩溃”当功能成立。
3. **主流程场景矩阵**：覆盖三练习、四节拍器、三倒计时；七卡片与编号、两端禁用、完整面板入口/收起/展开、录音共用状态、全部视觉组合和全局偏好跨练习、每练习声音隔离。新 UI 可沿用已有创建练习、笔记语音/照片、调速/TAP、持续播放和项目笔记回看测试的入口方式。
4. **计时与运行行为补充**：优先在统一运行命令与实际持久化边界注入可控时钟和设备适配，沿用 PracticeTimerTests / PracticeCountdownTests 的推进时间方式。静默练习120秒、暂停60秒只增加120秒，误差不超过1秒；录音30秒不再为零；主暂停/自行暂停交错不会误恢复录音；停止录音练习继续。相机/全屏/导入展示不误退出或重复计时；相机中到零时练习时长截至截止点，视频仍可保存。
5. **到零与保存幂等**：沿用现有倒计时完成一次、音频截止和 PracticeStore 重复保存不累计的测试先例。让音频与时钟同刻到零，验证一次完成、一次媒体关系、不自动完成练习；重复返回/完成、重复 UI 回调不增加时长或附件。倒计时保存计划不启动、复位不清实际时长、离开取消均需验证。
6. **最低必要音频时序补充**：复用 MetronomeEngineTests、MetronomeTempoControllerTests、Meter/Subdivision 与声音资产测试。验证拍号/重音/细分原子边界、6/8计拍单位、预备与正式小节、pause/resume保留计数、试听两小节不污染正式状态；已排入 buffer 时换预设，实际下一发声事件换色且相位不变，不仅 assert 属性。验证静音保留音量/时间线、拍手不强制闪拍、音量钳制、会话启动失败回滚、后台不发前台视觉，以及14份素材格式/长度/峰值契约。
7. **故障与文件所有权补充**：在现有 PracticeStore 和文件服务边界做故障注入，沿用内存 repository、临时目录、媒体保存回滚、NoteImageStore 三张上限/跨练习隔离和迁移测试先例。覆盖600ms防抖后保存最新文本、过期回调不覆盖、退出flush、失败重试、取消/损坏文件、拒绝权限、重复导入、数据库/磁盘失败；失败保留草稿/pending且只清理本次新增文件。验证原项目笔记投影、历史权限、旧库与稳定rawValue解码，不为测试重造数据库服务。
8. **真机与辅助功能验证**：模拟器用于稳定流程与截图，真实麦克风电平、相机、静音模式主动播放、录音共存、扬声器/有线/蓝牙路由、锁屏/后台、来电、音频服务重置及两小时连续基线必须记录真机结果。标准屏、SE 3窄屏、大字号、VoiceOver、减少动态效果和深色外观下的指定白底面板均需可操作。缺设备标未验证，不能伪报通过。
9. **听辨与验收结果**：提供同节奏80/160 BPM及密集细分 A/B，需求方明确选择木质/电子/强拍候选；记录音色偏好、辨认、刺耳和疲劳，不用波形替代听感。正式交付包括十场景对照、自动化结果、真机矩阵、音色选择与未测项；目前没有运行或通过这些产品验收。
10. **指标边界**：功能用例通过率100%、计时误差不超过1秒、测试样本中丢失/重复累计/误标完成为0作为验收目标。PRD 另提无协助任务完成率≥90%、四周保存可信度≥4/5及音色评分建议，是未测且未单独确认的效果假设，不是 ready-for-agent 的额外产品前置条件。不新增隐含分析系统或上传笔记/音频；无样本就标样本不足，不声称群体改进。

## Out of Scope

- 新增云后端、登录、跨设备同步与同步冲突解决；本轮后端仅为本地业务服务。
- 项目默认节拍配置、步骤稳定身份、步骤覆盖/恢复跟随及多级继承；同项目练习仍各自保存声音和节奏。
- 用“标准/穿透/高噪声”三模式替换七个现有预设，环境监听、自动判断噪声、自动切换模式、自动开启振动/闪拍、改系统音量或强制路由。
- 可下载/上传音色、音色市场、PDF/乐谱解析、未定义的细分第二页、新 AI 点评或首页问卷/方案重做。
- 独立项目笔记副本、步骤级计时、第二份练习事实或将方案汇总/媒体元数据当额外时长。
- 因指标新增云埋点、功能放量平台或继承旧票的三模式发布架构；这类能力需独立范围。
- 将整面板扁平化为截图、导入预览字体替代系统 Dynamic Type、无必要改全局主题或已发布 schema。
- 自动部署或发布应用，以及自动修改/关闭已有冲突 Issue。
