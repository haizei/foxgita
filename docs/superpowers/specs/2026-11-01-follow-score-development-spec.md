# Gita 跟谱练习：整体开发规格

状态：Q1–Q14 已确认，2026-11-01 用户授权按完整规格进入开发。实现与验收证据单独记录，范围确认不代表能力验证已经通过。

## 1. 目标、设计与现有基础

将“选谱—校正—跟练—标难点—再练—记录”做成原生 iOS 的完整可用流程，而非播放动画。整体包含完整和弦、扫弦节奏与综合评分，不擅自缩减为单音调音或仅内置谱。

- 设计：[工具页](https://www.figma.com/design/smeuuUaTOYE1URHhIGbzyd/?node-id=2408-112)、[V3 品牌谱面](https://www.figma.com/design/smeuuUaTOYE1URHhIGbzyd/?node-id=2788-821)、[A–E 完整流程](https://www.figma.com/design/smeuuUaTOYE1URHhIGbzyd/?node-id=2805-1501)。
- 工程：SwiftUI / SwiftData，最低 iOS 18，`foxgita.xcodeproj` / `foxgita` scheme。工程当前 schema V19，后续迁移从实施时的真实版本继续递增，不覆盖其他变更。
- 复用：PracticeStore、PracticeTimer、PracticeRuntimeCoordinator、PracticeEntryGate、AudioSessionCoordinator、现有节拍器和调音组件。
- 新建：交互曲谱模型和目录、识谱服务与校正、跟谱运行与谱面、长期难点及续练位置、真实演奏识别与评分。
- 领域边界：[CONTEXT](../../../CONTEXT.md)、ADR-0013–0016。事实与逐轮确认见 [访谈](../../design/2026-11-01-follow-score-development-interview.md)。

## 2. 已确认的交付范围

| 模块 | 交付行为 |
| --- | --- |
| 三条入口 | 从今日创建跟谱、在已有练习关联曲谱、从工具选择当天练习或新建当天项 |
| 曲谱来源 | 内置原创练习谱；印刷六线谱和五线谱 PDF/图片，含清晰拍照；手写、简谱不是已确认范围 |
| 自动识谱 | 产品内置云端服务，上传前告知；识别结果先预览和校正，用户确认后才可跟练 |
| 校正工作台 | 原谱对照，改正音高/弦品、时值、拍号、小节线、和弦；不做从空白制谱或重编整曲软件 |
| 工作台 | Gita V3 风格的六线谱/五线谱及 V2 已要求的双谱同屏，亮暗外观，谱面上方歌词区、和弦及节拍指示；按可用曲谱内容显示 |
| 练习模式 | 持续走谱、实时听弹反馈、可慢速和 A–B 循环；不是等弹对才推进 |
| 演奏模式 | 按选定整段/整首连贯进行、结束复盘；不把改速循环的练习结果冒充原速整曲演奏成绩 |
| 识别与评分 | 完整和弦、扫弦节奏与综合评分；可靠验收环境为吉他声＋耳机伴奏 |
| 难点 | 每首曲谱保存多个难点，含名称、小节范围、速度、循环次数、备注和掌握状态；下次直接专项练习 |
| 续练与记录 | 续练位置和难点分开；实际时长归当天 PracticeItem，已有时长/笔记保留；历史不追加 |
| 生命周期 | 锁屏/退后台暂停发声、监听、计时并保存，前台由用户恢复；独立节拍器后台规则不变 |
| 音源 | 确认曲谱生成示范音＋节拍器，内置原创谱可带原创伴奏；不加入个人伴奏导入对齐或自动寻找原曲录音 |
| 数据上传 | 实时听弹和评分在本地处理；仅谱页告知后上传，弹奏音频不上云，主动录音保存属于本地练习媒体 |

双谱同屏沿用 V2 已要求的音乐信息同步方式，视觉统一到 V3；两个谱面引用同一版本和音乐时钟，不复制出两个独立播放过程。不从旧版连击画面推导额外连击倍率规则。

设置包含示范音/节拍器/可用原创伴奏的音量与开关、谱面切换、歌词/和弦显示、调音器入口。歌词为空时保留合理布局，不制造不存在的歌词。打开调音器前暂停跟谱并交还麦克风所有权，退出后由用户明确恢复。

## 3. 用户旅程与页面

### 3.1 今日练习创建（A）

创建练习 → 选择跟谱练习 → 我的曲谱 → 选谱/预览 → 选择范围、速度和谱面 → 创建当天项并进入工作台。重复点击只消费同一入口身份一次，不创建多个空项。

### 3.2 已有练习关联（B）

当前练习 → 关联曲谱 → 确认曲谱与范围 → 开始跟谱。保存原有笔记、媒体和累计秒数，不因关联/更换曲谱清零。未完成的当天项沿用；已完成项与历史项继续练时另建当天项，避免改写已经结束的事实。

### 3.3 工具快捷进入（C）

工具“跟谱练习” → 最近曲谱/我的曲谱 → 开始前选择当天未完成练习或新建当天项。离开选择弹窗不启动监听、不累计时长，也不创建空记录。

### 3.4 PDF/图片识谱与校正（新增流程）

导入 PDF、相册或清晰拍照 → 文件与页数检查 → 预览/裁切与方向确认 → 上传告知 → 创建识谱任务 → 展示逐页状态 → 原谱与结果对照校正 → 曲谱元信息/音乐约束检查 → 用户确认 → 进入我的曲谱和准备跟练。

- 多页保留顺序和原页坐标；局部失败可只重试对应页，取消不产生可跟练曲谱。
- 内容与低置信记号必须可定位到原页；文件上传成功不显示成“曲谱已正确识别”。
- 节奏、小节结构或必要调弦信息不完整时明确列出待处理项；用户校正和确认前不评分。
- 原谱没有速度、调弦或变调夹信息时明确请求补全/确认，不静默以假定值产生目标音高或播放速度。
- 识谱仍无法支持的记号应提示具体位置；不悄悄删掉记号后标记成功。
- 目标为六弦吉他；多谱表原稿需确认目标声部。五线谱自动推导的弦品是可校正的排指建议，不能标成原稿已经提供的指法。

### 3.5 难点专项（E）

工作台暂停/圈选 A–B → 标记难点 → 编辑名称、速度、循环次数和备注 → 保存到曲谱 → 我的难点 → 开始专项 → 按范围/练法运行 → 保存实际练习与结果，难点仍可下次使用。

“继续上次进度”恢复播放位置；“我的难点”选择长期片段；“从头练”回到当前整曲/片段起点，均不删除历史时长。已掌握状态由用户明确操作，不因练满五次或得高分自动改变。

## 4. 音乐时间、范围与运行规则

以下是待最终整体核对的实施默认规则：

- 音符/休止/和弦位置依附曲谱版本和音乐时间，速度、拍号、计拍单位显式表达；不可把屏幕像素、音频秒数或节拍器当前小节数当曲谱永久位置。
- 范围采用起始音乐位置与结束边界，完整表示第9–12小节；显示编号与内部身份分开，反复段展开后的播放次序与纸面小节号分开。
- 声音、视觉游标、歌词/和弦与听弹匹配共享同一音乐时钟映射，暂停、跳转、速度改变后重新建立一致的时间基准。
- 预备默认一个当前拍号的小节，不计入正式小节、循环完成数、实际练习累计或评分；进入正式跟练时启动/恢复唯一实际计时。
- 完整播完 A 到 B 才增加一次循环数；暂停、拖动、跳段、预备、识谱/设置停留均不算完成一轮。
- 有限循环完成后停止本轮专项并复盘，可再练；结束片段不自动把整条练习标为完成。
- 暂停时调整速度立即准备新配置；播放中改变速度在确定的音乐边界原子生效，界面可区分待生效与当前生效速度。不能声音已变、识别目标仍按旧速。
- 改 A–B 时先暂停并确认新范围，从新 A 起重新预备，不将跨范围残余播放算完整循环。
- 慢速练习显示速度倍率和实际 BPM/计拍单位；与原速演奏结果分别标识，不以慢练分数代表原速能力。
- 重启、来电、输出耳机丢失、音频服务重置等恢复均不自动发声；重连后由用户明确继续。
- 所有速度与时间单位遵循现有 Beat Unit 语义，避免导入谱的四分音符 BPM 与现有按分母计拍的节拍器 BPM 混算。
- 演奏模式默认按原速连续完成选定整段/整首，不开启片段循环；要跳段、改速或重新圈选时结束当前演奏尝试，切回练习配置。中断/提前结束保留部分结果，不标成连续完整演奏。
- 由确认后的曲谱在本地合成示范音；改变速度、跳转或循环时示范音、节拍与视觉一起改变。内置原创谱如带配套伴奏，也必须使用同一音乐时间映射。

## 5. 听弹反馈与评分

- 在目标曲谱已知的上下文中评价用户实际演奏，不用播放音符自动制造命中，也不把调音器单频读数当完整和弦识别。
- 音高/和弦正确性、起音/进拍、扫弦节奏与演奏覆盖分别表达；综合分必须能解释对应维度和范围，并关联到具体曲谱版本、速度、模式与实际尝试。
- 和弦以目标谱实际组成音及发声时间评价，不能只对少量固定名称给成功状态；验证覆盖开放和弦、横按、强力和弦、转位/八度重复及谱中扩展音。物理按弦方式与同音弦品仍不能靠单通道声音唯一推断。
- 和弦同时发声与扫弦分次发声需有不同的匹配窗口；延音、休止、连音与反复按目标音乐内容处理，不能每一帧重复判同一个音。
- 音频输入时间、输出时间及设备延迟校准与 UI 动画时钟分开。识别结果按采样时间落到音乐位置，不按计算完成的时间判“迟到”。
- 可可靠采集但没有按预期演奏与无法可靠判断是不同结果。权限拒绝、输入缺失、削波/强噪声或分析失败不可伪装为全部弹错或全部正确。
- 对无法判断的范围显示覆盖情况和原因；覆盖不足时不输出看似精确的完整综合分。不允许靠跳过难判音符得到虚高成绩。
- 仅凭手机声音无法唯一确定同音对应的具体弦品、按弦手指或物理扫弦方向；六线谱可以指导这些动作，但不能宣称仅靠音频证明它们正确。
- 外放伴奏与边唱边弹不是本轮同等可靠性验收承诺；遇到无法判断应可继续无评分跟谱并调整环境，而非卡死核心练习。
- 实时音频分析、匹配和评分全部在设备上执行；没有上传音频才能工作的兜底方案。设备资源或输入不可用时明确显示原因，并能继续无评分跟谱。
- 默认不持久化原始监听音频；仅用户主动录音才保存到现有本地媒体体系，按原有规则处理录音生命周期。

## 6. 数据、所有权与历史

建议领域对象（逻辑模型，不预先锁定表/文件布局）：

| 对象 | 保存内容与边界 |
| --- | --- |
| 曲谱材料 | 所属档案、标题/作者、来源、目录状态；长期复用，不累加练习时长 |
| 曲谱版本 | 确认后的音乐内容、调弦/变调夹、谱页映射、时值/拍号/速度、内容版本身份 |
| 谱页原件 | PDF/图片文件与页顺序，可对照识谱草稿；不等同笔记图片附件 |
| 识谱任务/草稿 | 上传与处理状态、页级结果、待校正记号、修订及用户确认；未确认不进入已可跟练目录 |
| 练习关联 | 当天 PracticeItem 引用具体曲谱版本及准备范围；保留原计时、笔记和媒体 |
| 难点片段 | 曲谱版本、稳定范围、名称、速度/循环、备注和用户掌握状态 |
| 续练进度 | 独立的上次有效音乐位置、速度/范围/谱面配置；不覆盖难点列表 |
| 跟谱运行/尝试 | 一次真实练习的范围、模式、配置、结果及 PracticeItem 引用；实际时长不另设第二份可累加真理源 |

- 草稿修订不覆盖已确认历史版本。确认修正后保留旧版引用；音符/小节结构变化使旧难点不再可直接映射时，明确要求复核范围，不静默把旧难点移到另一段。
- 删除/归档曲谱后仍能解释历史练习引用；已结束记录和原评分快照不可因换谱、修谱或改名被改写。
- 所有材料、难点和关联遵守当前档案隔离，不能按歌曲标题认定唯一曲谱或跨档案泄露进度。
- PracticeStore 仍写绝对累计秒数；跟谱保存以稳定运行身份/保存身份做到重试不重复计时，重复结束不重复创建结果。
- 同一天未完成项继续沿用；明确完成后再练创建新项。跨天按本地日期创建/拆分实际事实，不追加昨天；恢复曲谱和难点与旧项是否可写分开。
- 保存曲谱/进度失败时保留可恢复状态，不先显示“已保存”；记录保存失败与云端识谱失败分开处理。

## 7. 云端识谱边界与失败恢复

- 正式客户端通过产品服务访问识谱，服务商密钥不打入 iOS 包；具体认证、限流、费用与供应商按现有工程能力和技术验证确定。
- 当前工程只有设置页中的用户自配 AI 接口与用户 LLM Keychain；没有现成托管后端、登录/刷新 token 或识谱任务认证。Q10 需要新增产品服务与独立客户端，不读取用户 Base URL/Model/API Key，也不把 LocalProfile 的本地 UUID 当服务端可信凭据。
- 可复用 URLSession 注入、错误映射与 Keychain 存取模式；不能直接复用自动追加 chat/completions、只解析文本回复的 AITransport 作为识谱协议。
- 云端仅处理已经告知且发起导入的谱页；保存本地原件与任务身份，失败重试不重复生成曲谱或产生多个成功状态。
- 服务应支持任务状态、取消、页级错误、超时、可重试失败、校验失败与服务不可用；前端显示明确的下一步，而非一直转圈。
- 提交/识别/校正/确认是不同状态，回调晚到不能把已取消或已归档任务重新变成已确认曲谱。
- 文件类型、页数、解码尺寸、资源占用及请求容量设显式边界，并在上传前提示；实际数值随经验证的部署容量配置，不拿模型“支持图片”推断无限容量。
- 本轮没有实际上传谱页、采购服务或部署新服务；Q13 已明确禁止本功能上传听弹音频，服务请求与日志都不可携带原始监听内容。
- OMR 选型需分别证明 TAB 与五线谱能力；渲染器、MusicXML 支持或消费级识谱 App 都不能代替 Gita 可用的服务集成。

## 8. 实施结构与阶段依赖

1. 能力验证：真实谱页识别、可编辑的音乐内容、原生工作台时钟、设备端耳机环境和弦/扫弦识别。完整范围不变；先验证不代表只交付示例。
2. 曲谱领域与迁移：材料/版本/草稿/难点/续练，PracticeItem 关联和唯一时长写入；失败可恢复。
3. 内置原创谱与核心工作台：单音旋律、和弦转换、扫弦节奏各一条原创练习内容，真实本地示范发声、游标、暂停/跳转/变速/A–B、两种模式、歌词/和弦/谱面设置。
4. A–C 入口与 D 保存闭环：复用当前练习、关联/换谱、跨天和结果记录。
5. E 难点与专项：标记、管理、重练、状态、续练位置区分。
6. 云端导入与校正：PDF/图片到任务、逐页草稿、对照校正、确认曲谱、取消与重试。
7. 完整听弹反馈与评分：接入经过验证的分析器和时间对齐，按真实可解释结果呈现。
8. 全旅程回归、持久化升级、无障碍/明暗适配、真机音频验收。

阶段 1 的识谱和音频验证是后续引擎决策的依赖。没有真实能力证据时应报告具体缺口，不把占位服务或伪造评分当作完成。

| A 入口创建 | 选谱/准备后进入当天项；取消不产生空项；连点不重复创建 |

| 真实跟谱 | 发声、谱面、歌词/和弦、识别目标按同一音乐位置一致前进；不是定时播放固定 UI 图案 |
| 谱面与设置 | 六线谱、五线谱、双谱在同一位置切换/同步；歌词和和弦开关真实生效；打开调音器先暂停跟谱 |
| 循环 | 第9–12小节只在完整走完后记一轮；暂停、跳段、调整范围不误加次数 |
| 难点 | 保存两个不同难点；次日仍可分别恢复范围/速度/备注并专项；上次进度不覆盖它们 |
| 暂停与锁屏 | 声音、监听、计时停；后台间隔不计时；返回不自动发声；独立节拍器行为不回归 |

| 识谱 | 用独立打印 TAB、五线谱、混排、清晰拍照、多页样本逐项核验音高/弦品/时值/小节/原图定位 |
| 校正 | 能把一处错误音高、一处错误时值及小节结构问题改正确认，并在播放与反馈中使用修正内容 |
| 导入失败 | 网络断开、页失败、取消、超时、重复回调可恢复；没有半成功的可跟练曲谱 |
| 完整听弹 | 在耳机环境分别使用真实吉他和弦、换和弦、扫弦节奏录样，验证正确/错音/漏音/早迟/休止，不能只测合成音或单音 |
| 评分可信 | 低覆盖、不可靠输入和正常未弹区分；成绩定位到版本、范围、速度和模式，无输入不产生假命中 |
| 听弹不上云 | 断网仍可对已确认本地曲谱发声、听弹和评分；识谱请求不含原始弹奏音频，网络失败不阻断本地听弹 |
