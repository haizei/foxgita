# 原谱跟弹开发规格

版本：**v1.1，2026-11-07**。当前需求以用户最新纠正“不是让人标记，而是直接读取谱子后跟练”为准。

## 当前流程修订（优先于下文 v1.0 历史条款）

- 入口方案 3 与整页方案 1 保留；上传图片/PDF 后自动读取，成功即保存到我的曲谱并直接进入跟练待机。删除“标记谱行”必经页和“保存并跟弹”确认步骤。
- 本机自动读取谱行、小节边界及拍号，按页从上到下建立播放行；行总拍数为已读小节数 × 拍号分子。没有读出拍号时沿用练习设置并在跟练页明确显示。
- 不要求用户框选、逐行填写拍数或手动排序。首版面向清晰正向的六线谱、五线谱；布局读取不等于逐音 OMR，不承诺弱起、不完整小节、变拍、自由速度或反复跳转的精确还原。
- BPM 标为“练习速度”，沿用当前设置/80 BPM 默认值；不声称已读取原曲速度。整行匀速、可选节拍器、全部行弹完停止、范围与循环、3 秒准备的位置及运行规则均保留。
- 上传先保存待读取材料；关闭/读取失败保留原文件，允许重试和删除。所有页面必须成功，边界不明时显式报错，不猜一行一小节，也不返回手工标记流程。
- “重新读取”代替“修改标记”，成功产生新版本，新行身份重置进度、范围为全部行、循环关闭；旧版历史原样保留。已有手动标记版本保持可播放兼容。
- 长期保存、20 页/30 MB、40–200 BPM、按发生日记时、准备不计时、后台暂停、跨次从所在行开头待机、历史保留规则沿用下文。
- 验收：上传后无需任何画框/拍数输入即可待机、三秒准备及播放；自动读取四行十六小节样例；空白、缺小节线或失败页不能自动发布；取消不能延迟发布。

决策见 [ADR-0021](../../adr/0021-automatically-read-original-score-before-practice.md)。

## 1. 目标

让用户不等待识谱、不校正音符，也能用自己已有的谱页开始节奏练习：选择原谱跟弹 → 导入图片/PDF → 标记谱行 → 保存至我的曲谱 → 原谱整页跟线。整行匀速是用户已选择的首版精度，不承诺音符与游标逐一对应。

实施对象为 `foxgita/` 中的 iOS SwiftUI/SwiftData 工程；`score-line-prototype/` 和 Figma 用于交互与视觉参考，不作为持久化或运行计时实现。

### 原型与开发规格的差异

网页原型里的 12 页、30–240 BPM、每行默认 4 小节、默认选中 2–3 行循环，以及浏览器刷新即丢失，仅为原型行为。开发按 Q1、Q4、Q9、Q15：材料持久化、自动留草稿、20 页/30 MB、40–200 BPM、首行默认 1 小节、首次全部行且循环关闭。调整现有实现时，不从原型反推默认值。

## 3. 与既有原谱能力的关系

- `ScoreDocument` 的原谱小节已经要求有效小节框、页码与 sourceID；手动谱行可以覆盖多个小节，两者不可直接等同。
- ADR0017 的原谱视图基于确认过的小节结构；本轮允许手动标行后直接开练，补充的是新练法路径。
- 不能通过伪造休止符、空音乐事件或“已经识谱成功”状态绕过现有发布校验。
- 既有曲谱跟练的识谱、校正、发声与评分边界保持各自适用范围。
- 工程设计采用独立的手动谱行文档，与现有结构化曲谱通过带类型的材料引用接入同一曲库和练习归档；不会把手动谱行强塞进 `ScoreBar`。下文的数据合同是开发建议，尚非已存在实现。

## 4. 体验流程

| 步骤 | 用户看到 / 操作 | 输出或下一步 |
|---|---|---|
| 选择练法 | 创建练习 → 跟谱练习 → 原谱跟弹 | “上传谱子”入口 |
| 导入 | 选择图片/PDF，预览谱页 | 可编辑的谱行标记草稿；不得投影成待识谱任务 |
| 标记 | 选定谱行区域，填小节数或调整行总拍数；检查自动排序并可调整 | 自动保存标记草稿；拍以拍号分母为单位，0.5 拍递增，可设置弱起 |
| 保存 | 默认文件名作为可编辑曲名；至少一行有效标记后“保存并跟弹” | 保存原件与标记版本，加入我的曲谱；不会自动开始播放 |
| 跟弹 | 入页待机，按普通播放开始；原谱整页显示当前位置 | 可选节拍器；全部行一次播放为首次默认 |
| 准备 | 点击范围右侧的“3 秒准备” | 3→2→1 后从当前位置开始；可取消；准备期间不走线、不计练习时长、不响正式节拍 |
| 结束/续练 | 归档实际弹奏时间，保留可复用材料 | 同次精确暂停；跨次从所在行开头待机；完成后回所选范围起点待机 |

标记页需支持新增多行、选中已有行后调整框位置/大小、修改拍数、删除与调整演奏顺序。新增行有独立身份，不能复用同一个标记对象覆盖上一行；只有编辑选中行时才更新该行。编号表示当前演奏顺序，重新排序后同步更新编号。自动排序使用页码和从上到下位置作为初始顺序；用户确认过的手动顺序不能因缩放、重绘或重新打开而丢失。

上传后已有有效标记时可“保存并跟弹”；没有有效行时解释需要先标记，自动草稿保存仍可进行。保存成功后进入待机；“3 秒准备”保持在训练范围控件右侧，与普通播放入口清楚区分。运行时切换当前行应滚动/翻页使其可见，仍保留原谱完整页面内容。

## 5. 时间与运行状态

### 行总拍数（Q5 已确认）

全曲使用统一速度、拍号和行总拍数：

- 行的小节数可按全曲拍号换算总拍数；总拍数可直接调整以表达非完整行。
- 例如 4/4 的 3 小节＋2 拍为 14 拍；不得向上补成完整小节或填入虚构休止符。
- 指示线的横向位置由该行已完成时间 / 该行总时长计算；不将音符横向间距解释为真实时值。
- 拍以拍号分母为单位；行总拍数为正、有限且按 0.5 拍递增，最小 0.5 拍。小节数作为快捷输入，实际保存行总拍数；修改总拍数后不再保留与之冲突的小节数。
- 设行总拍数为 `B`、BPM 为 `v`，则行时长 `T = B × 60 / v` 秒。4/4、80 BPM、14 拍为 10.5 秒；6/8、80 BPM、2 小节为 12 拍、9 秒。
- 设行内已经完成 `b` 拍，行框为 `(x, y, width, height)`，线的位置为 `x + width × clamp(b / B, 0, 1)`；只有进入下一行时才跳转。音乐位置以拍表达，与累计实际秒数分开；调速先暂停，保持 `b` 不变，明确播放后按新速度推进。
- 无节拍器声音时仍有稳定推进时间源；正式运行不能依赖界面 Timer 逐次累加充当音频同步时钟。

### 半拍、弱起与相位（Q12 已确认）

设拍号为 `N/D`，首行起始拍位以零基偏移 `s` 保存，默认 `s=0`。界面按“第 1 拍”“第 4 拍”等显示，半拍用“第 4 拍后半拍”表达；`s` 在 `[0,N)` 内，按 0.5 拍递增。

第 `i` 行前已经走过的总拍数为 `Pᵢ = Σ Bⱼ (j<i)`；行内位置为 `b` 时，小节内相位为 `(s + Pᵢ + b) mod N`。强弱模式按此相位访问，不在每行、跨页或片段开头强制重置为第 1 拍。片段起点使用对应行在完整材料中的 `Pᵢ`；循环回到该范围起点的原相位。

- 4/4、首行从第 4 拍开始：`s=3`。首行 1 拍后，下一行从第 1 拍开始；不会把弱起那一拍误当成首拍强音。
- 4/4、首行从第 1 拍开始且长 14 拍：下一行从第 3 拍开始。选中下一行单独练，也从第 3 拍相位进入。
- 整拍点击和细分点击根据同一全曲拍网格调度；从半拍中途继续时不额外补一个起始强拍。暂停/恢复、循环边界不能重复发出同一边界拍点。
- 拍数输入可使用半拍整数单位存储，避免浮点取模改变半拍边界；运行中的位置仍需连续插值。半拍精度限制适用于用户标定，不限制播放游标只能每半拍跳动。

### 顺序与跨页（Q6 已确认）

- 默认按页码、从上到下排列；允许手动排序并保存用户确认的顺序，兼容双栏等排版。
- 所选范围应引用稳定的谱行身份，避免删除/插入一行后范围静默指向另一行。
- 换行/翻页不自动添加准备时间或练习时间。

### 运行状态（Q7 已确认）

待机 / 准备中 / 播放中 / 暂停 / 范围完成。准备是独立状态，不等于原 `ScoreRun` 的一小节 count-in，也不等于限时训练的剩余时长。

| 当前状态 | 操作或事件 | 结果 |
|---|---|---|
| 入页 | 页面可用 | 待机，不自动推进，不累计练习时长 |
| 待机 / 暂停 | 普通播放 | 从当前位置立即开始/继续 |
| 待机 / 暂停 | 3 秒准备 | 保存当前位置，进入固定 3 秒准备 |
| 准备中 | 倒数完成 | 从准备前位置开始/继续 |
| 准备中 | 取消、离开前台 | 回到暂停，保留准备前位置，不自动补完倒数 |
| 播放中 | 暂停、离开前台 | 停止推进并暂停实际练习计时；恢复需要明确操作 |
| 播放中 | 普通行尾 / 页尾 | 按确认顺序进入下一行，不增加停顿 |
| 播放中 | 所选范围末尾、循环关闭 | 范围完成，停止推进与计时 |
| 播放中 | 所选范围末尾、循环开启 | 直接回到范围起点，不重复 3 秒准备 |

准备中的线不移动，不累计练习时长，不播放正式节拍。仅播放中累计实际时长；材料总时长、准备倒数和暂停停留均不替代实际弹奏时长。完成态再次播放从所选范围起点开始。

### 播放中修改（Q14 已确认）

| 修改 | 生效与位置处理 |
|---|---|
| 节拍器开关 | 即时生效，保持音乐时钟和位置；不因静音暂停或重启 |
| BPM | 先暂停，保留行内拍数；用户明确播放/准备后用新速度继续；不修改原谱版本 |
| 训练范围 | 先暂停，再落到新范围起点待机；范围选择本身不自动打开循环 |
| 进入标记编辑 | 先暂停，在修订草稿中编辑；未保存不改变当前版本 |
| 仅修改行框 | 保存新版本，保留行身份、范围、进度和循环设置 |
| 拍号、起始拍位、行拍数、行顺序或行集合变化 | 保存新版本，进度回到全部谱行起点，范围设为全部行、循环关闭，待机 |

准备期间更改速度、范围或进入编辑，先取消准备，再执行上述规则，不能让旧倒数结束后自动开始。

### 持久化、修订和恢复（Q9–Q11 已确认）

- 标记草稿与已入库版本分离。草稿恢复不启动识谱、不计练习时长；保存失败保留可重试草稿，不能展示虚假的已入库状态。
- 保存成功产生不可变版本；随后修改在新草稿中进行，取消修订不改变已保存版本。历史练习固定引用当时版本，不随最新版本改写。
- 仅修改行框位置且谱行身份、顺序、拍号、起始拍位和拍数不变时，保留练习位置与范围。增删行、改顺序、行拍数、拍号或起始拍位后，重置到全部行起点、循环关闭。
- 同次暂停保留行 ID 与行内拍数；退出后重新进入，将恢复位置投影到该行开头。已完成则投影到所选范围开头。全部恢复均以待机进入。
- 范围以有序谱行列表中的起止行身份表示，连续选择整行；图示“2–3 行”为选后摘要。当前版本解析行身份失败时不得静默改指另一行，必须明确恢复到可用范围。
- 曲库删除是隐藏材料，保留历史及其引用版本、谱页。任何仍被草稿、版本或历史引用的原件均不得被清理。

| `ScoreRun`、`ScoreRuntimeModel` | 一小节预备、训练页自动开始、音频时间推进 | 固定3秒与无音频推进必须显式适配 |
| `PracticeStore` / checkpoint | 每5秒幂等落库并处理跨天 | 接入同一实际时长链，不新增第二份累计 |

现有工作区有无关未提交改动。本轮仅编写文档与术语，不调整产品实现、工程文件或旧测试。

### 节拍器继承的接口约束

普通节拍器的 BPM 以所选拍号分母为主拍单位，曲谱引擎则以独立 `ScoreTempo.beatUnit` 解释 BPM。以 6/8、80 BPM 为例，普通节拍器每小节 4.5 秒；曲谱引擎默认 `beatUnit=4` 时为 2.25 秒。Q8 已确认新模式沿用普通节拍器的语义，接入必须显式携带分母拍单位或等价换算，不能仅传同一个 BPM 数字。界面展示“♩ = 80”或“♪ = 80”等与拍单位一致的说明。

“沿用练习设置”需要增加桥接：当前 `ScoreAudioEngine` 未读取 `PracticeItem` 中的强弱、细分、音色、音量与强拍增强。按第 8 节解析各项来源；现有 BPM 恢复查询仅恢复 BPM，不能当作整套配置继承。

验收必须包含非 4/4 拍号，分别核对整行耗时、拍点数量、声音强弱与游标同步；不能只用 4/4 测试掩盖单位差异。关闭声音也应使用相同的拍单位与时间投影。

## 7. 已确定的验收方向

1. 原有曲谱跟练仍进入原曲谱库；原谱跟弹不调用识谱和校正流程。
2. 手动标记能显示在原始谱图正确位置；行框不遮挡谱面；连标多行不会覆盖上一行。
3. 首次默认全部标记行，完成后停止；图中的“2–3 行”不是全局默认。
4. 材料可在我的曲谱再次打开；跨次从所在行开头待机；修订保留历史版本，修改结构后重置进度。
5. 节拍器关闭时指示线仍连续推进；开启时共用一致的音乐时间依据。
6. 准备按钮位于范围右侧，可见3、2、1与取消；入页待机、普通播放立即开始；准备期间不走线、不计练习时长、不响正式节拍；取消或退后台停在准备前位置。
7. 原谱路径不出现没有真实依据的音符示范、识别成功或评分。
8. 正常结束、暂停、退后台和跨天均不重复累计或丢失已经确认的实际练习时长。

### 已确认规则的验收场景

| 场景 | 可检查的结果 |
|---|---|
| 保存一份含多页、多行标记的原谱后退出，再从我的曲谱打开 | 原件、行框和已确认顺序仍存在；恢复设置，从上次所在行开头待机。 |
| 首次打开刚保存的 5 行原谱 | 训练范围包含全部 5 行，循环关闭；运行到最后一行末尾后停止。 |
| 手动选择第 2–3 行，未开启循环 | 只播放选定范围一次；范围选择本身不隐含循环。 |
| 在同一行的四分之一、二分之一、四分之三时刻检查线的位置 | 位置分别对应框内宽度的四分之一、二分之一、四分之三，不按原图音符疏密改变速度。 |
| 同一原谱分别开启与关闭节拍器 | 两种情况下线均能推进；开启时发声与线共用音乐时间；不出现音符示范音或演奏评分。 |
| 今日练习中打开昨天保存的原谱 | 曲谱仍是同一份长期材料；新增实际时长进入今天练习，不改写昨天记录。 |
| 4/4 的一行输入 3 小节，再改为 14 拍 | 保存 14 拍，不自动补成 16 拍；线按这 14 拍的总时长匀速走完。 |
| 调整双栏谱的行顺序后保存 | 按用户确认顺序播放，换行、跨页均不额外等待。 |
| 准备倒数到 2 时取消或退后台 | 线仍在准备前位置，实际练习时长未增加；重新回前台不会自动开练。 |
| 选中 2–3 行并打开循环，运行到第 3 行末尾 | 立即从第 2 行起点接续，不再次倒数，也不在边界重复累计时间。 |
| 6/8、80 BPM 的一行设为 2 小节 | 12 个八分音符拍、共 9 秒；不会按四分音符 BPM 算成 4.5 秒。 |
| 标记两行后退出，再进入草稿 | 恢复标记，不成为待识谱任务，不产生练习时长；显式保存后才进入我的曲谱。 |
| 旧版本完成练习后修改标记并保存，再查看旧练习 | 旧练习显示旧版本及原有时长；新练习使用新版本。 |
| 删除已有历史练习的原谱 | 我的曲谱中隐藏；历史记录及对应谱页仍可查看，时长不减少。 |
| 同次暂停在第 3 行中途，再继续；随后退出并重新进入 | 同次从行内原位置继续；跨次从第 3 行开头待机。 |
| 一行设 1.5 拍，4/4、60 BPM | 行耗时 1.5 秒，横向连续匀速；0 拍、负数、非有限数及非半拍步长值不能保存。 |
| 4/4 从第 4 拍弱起，第一行长 1 拍 | 首行按第 4 拍发声，下一行才到第 1 拍；跨行不多停或补拍。 |
| 第一行 14 拍后，选择第二行单独循环 | 第二行从第 3 拍相位开始，每次循环回到这一相位，不默认首拍强音。 |
| 没有当前练习时新建原谱；再次从另一个拍号的练习打开 | 首次为 80 BPM、4/4，节拍器关闭；再次保留原谱拍号和上次速度，不被当前练习覆盖。 |
| 播放到行内 2.5 拍时改速度，再继续 | 修改先暂停；位置仍为 2.5 拍，后续按新速度推进；准备/暂停时间不计入实际时长。 |
| 修改行拍数或拍号并保存修订 | 新版本选全部行、循环关闭、从头待机；旧历史版本和时长不改变。 |
| 只重新框选谱行位置，保持身份与时间结构 | 产生新版本，保留范围、循环与进度；历史仍显示旧版行框。 |
| 导入有未标行的页面 | 页面可查看；走线只经过已确认的有序谱行，不等待或推断未标内容。 |
| 新建首行、后续行以及删除全部行 | 首行默认 1 小节，后行沿用前行总拍数；没有有效行时不能保存并跟弹。 |

这些场景用于约束后续实现与测试；当前仅完成文档记录，尚未执行产品验收。

## 8. 设置优先级与输入边界（Q13–Q15 已确认）

“当前练习设置”指当前练习已解析出的有效设置，不直接把某个历史练习项的原始字段当作现值。材料拍号、练习速度和声音配置分别解析，不用一份来源覆盖所有配置。

| 设置 | 新材料首次创建 | 已保存材料再次打开 |
|---|---|---|
| BPM | 当前练习的有效速度，无当前练习则 80 | 材料上次练习速度；尚无播放偏好时用首次保存的速度 |
| 拍号 | 当前练习有效拍号，无则 4/4 | 材料版本拍号；只在标记修订中改变 |
| 音色、强弱、细分、音量、强拍增强 | 当前练习；无则现有节拍器默认值 | 当前练习；无则现有节拍器默认值 |
| 节拍器开关 | 当前开关，无当前设置则关闭 | 材料上次开关优先 |
| 训练范围 / 循环 | 全部已标记行 / 关闭 | 上次选择；结构修订后全部行 / 关闭 |
| 位置 | 全部行起点待机 | 上次所在行开头；完成后回所选范围起点，均待机 |

现有声音缺省包括默认音色、每拍一下、音量 80 和强拍增强开启，强弱默认为首拍强、其余普通。音色枚举沿用工程，不另造新值。声音设置须针对材料拍号校验；若来源强弱数组与材料每小节拍数不兼容，使用现有有效默认强弱模式，不能改写材料拍号来迁就声音数组。细分是每个分母拍内的细分，不按枚举英文名称再次换算拍单位。

- 导入：沿用当前导入器 **20 页 / 30 MB** 的校验口径；不为原谱路径另设原型中的 12 页限制。PDF 渲染与原件保存复用既有能力。
- BPM：有效区间 **40–200**；继承旧值时使用现有合法化逻辑落在区间内。界面和模型使用同一范围，不能仅在 UI 限制。
- 拍号：首版沿用现有节拍器支持的合法拍号集合；全材料统一拍号，不支持行间变拍号或变速标记。
- 新行：第一行默认 1 小节，即 `N` 个分母拍；后续新行沿用前一行总拍数。用户修改后以新值为准，不因行框宽度自动推测拍数。
- 保存：曲名取文件名作为可编辑初值，应用内选图无文件名时用普通的未命名标题；至少一行有效。所有待保存行都必须引用存在的原页、具有正宽高且处于页内、总拍数有效；不能静默跳过无效行后声称保存成功。
- 未标页：原件中保留，可查看；不生成虚构时长或隐藏空白谱行，不参与走线。只按用户确认的行顺序播放。
- 行框：保留原图纵横比，框坐标存于经方向校正后的原页坐标系；缩放/滚动只改变显示变换。当前行须处于可视区，换行与跨页不得等待图片动画完成才推进音乐时间。

## 9. 建议的数据与服务合同

本节为工程设计，不表示下列模型或接口已经存在；物理落库方式应沿用工程约定。所有材料、草稿、偏好和查询均隔离到当前 profile。

| 概念 | 最小数据 | 不变量 |
|---|---|---|
| 曲库材料引用 | 材料 ID、材料种类、当前版本 ID、隐藏状态 | 区分结构化曲谱和原谱跟弹；不能仅根据是否有音符推断类型 |
| 标记草稿 | 草稿 ID、sourceID、可选基础版本 ID、曲名、拍号、首行起始拍位、初始速度、行列表、保存时间 | 与识谱草稿分开；自动保存不产生练习事实 |
| 原谱标记版本 | 材料 ID、版本 ID、父版本 ID、sourceID、曲名、拍号、首行起始拍位、初始速度、行列表、创建时间 | 保存后不可变；历史只读；起始拍位按半拍表示 |
| 谱行 | 稳定行 ID、pageID、归一化行框、总拍数、演奏顺序 | 行框落在对应原页内，宽高为正；排序不改变行身份；拍数为正的半拍倍数 |
| 播放偏好 | 材料及版本引用、范围起止行 ID、速度、循环开关、节拍器开关 | 与材料版本、历史时长分开；按第 8 节解析 |
| 续练快照 | 版本 ID、行 ID、行内拍数、范围、完成状态 | 同次保留精确位置，跨次投影到行首；结构修订不能沿用失效行 ID |
| 实际练习关联 | 现有练习项 ID、材料/版本引用、累计实际时长提交身份 | 不从谱面总时长反推实际时长；回放或循环不能重复提交同一累计增量 |

建议新增独立的 `OriginalScoreDocument` / `OriginalScoreMarkingDraft` / `OriginalScoreResume`，通过带类型的 `PracticeMaterialReference` 接入曲库及归档。名称为建议；不得为了省一个类型而伪造 `ScoreBar`、识谱结果或音符事件。

| 服务操作 | 输入 / 输出 | 必须保证 |
|---|---|---|
| 导入原件 | 当前 profile、选择结果 → sourceID、可预览谱页 | 沿用导入器校验；失败不得留下可播放材料；取消选择无草稿 |
| 保存标记草稿 | 草稿和上次保存标识 → 确认保存标识 | 文件或数据库写入原子完成；较早的异步保存不能覆盖较新的编辑 |
| 保存入库 / 发布修订 | 有效草稿、基础版本 → 不可变版本与曲库引用 | 原件可读、全部待保存标记通过校验后才提交；重复点击不重复建材料或版本；基础版本冲突不覆盖新版本 |
| 打开材料 | 材料引用、入口归属 → 版本、偏好与待机快照 | 按现有 tool/newPractice/existing 归属解析今日项，不额外创建重复练习记录 |
| 修订迁移 | 旧/新版本、旧快照 → 保留或重置后的快照 | 仅几何变化保留稳定行 ID；结构变化重置；历史引用不迁移 |
| 运行与 checkpoint | 音乐位置、实际播放区间、提交身份 → 幂等归档结果 | 准备/暂停不计入；正常结束、退出与跨天使用同一累计链 |
| 隐藏材料 | 当前 profile、材料 ID → 隐藏状态 | 不删除历史或仍被引用的谱页；历史页面仍可解析旧版本 |

运行推进、节拍调度与视觉投影使用同一时间依据；静音不能停止该时间源。页面取消、退后台或销毁时停止当前准备/播放任务，使用运行代次或等价机制忽略过期倒数与音频回调，避免取消后突然开始。

## 10. 异常与一致性

| 异常 | 用户结果 | 数据结果 |
|---|---|---|
| 系统选文件取消 | 留在上传入口 | 无新增草稿或练习 |
| 文件过限、PDF 损坏/不可读、图片无法解码 | 显示具体失败原因，可重选 | 不入库；不提交识谱任务 |
| 行框越界/空框、无效拍数、无有效行 | 标出需要修改的位置，不能保存并跟弹 | 保留可编辑草稿，不能伪装保存成功 |
| 草稿自动保存失败 | 明确显示未保存并可重试 | 不丢当前内存编辑；退出不能提示已保存 |
| 保存版本失败或基础版本冲突 | 保留草稿，允许重试或重新加载 | 当前版本、旧版本和历史均保持一致，不能部分发布 |
| 谱页文件缺失 | 明确提示材料不可用，停止开练 | 不删历史，不用空白图继续走线，不增加时长 |
| 行 ID 或续练快照失效 | 明确提示恢复位置已重置并待机 | 不把旧行号静默套到另一行 |
| 音频打断、退后台 | 暂停，回前台等待用户操作 | 截止到暂停时刻提交实际时长，不补算后台时间 |
| 自动保存、重复结束、退出等回调交错 | 状态与最后一次有效操作一致 | 草稿保存和练习累计各自幂等，不能生成双份练习 |

## 11. 接入、迁移与实施顺序

1. 先实现独立原谱文档、稳定行 ID、归一化框、半拍校验、起始拍位和时间投影，测试非 4/4 的单位换算、弱起与片段相位。
2. 复用原件导入，增加带练法意图的标记草稿保存与恢复；确保不会进入现有 `pending()` 识谱列表。
3. 增加曲库材料类型、不可变版本及隐藏状态；已有曲谱按原类型解析，无需重写原有 `ScoreDocument` 或把旧 sourceOnly 小节转成手动谱行。
4. 接入创建练习的练法分段、上传、标记、保存和我的曲谱入口；保留原曲谱跟练导航与返回行为。
5. 实现整页显示、当前行可见、范围与稳定行 ID、统一时钟、固定 3 秒准备及可取消状态；接入第 8 节设置优先级和播放中修改规则。
6. 接入现有 `PracticeStore` 实际时长链、续练、跨天与生命周期暂停；完成修订迁移、删除后历史查看和异常处理。
7. 执行纯模型、存储、运行与端到端验收；本轮只完成文档，不将未运行的用例标记为通过。

增量迁移需要给旧记录提供兼容的材料类型与可空的新关联字段；优先复用当前持久化设施，是否需要 SwiftData schema 升级取决于最终存放位置。不得因这次新增入口清空或重新累计旧练习时长。

验证分层：纯模型覆盖拍数/时间/行框/顺序；存储覆盖草稿、不可变版本、恢复与引用保留；运行覆盖倒数取消、生命周期、静音时钟、循环和幂等归档；端到端覆盖“上传→标记→保存→准备→跟弹→退出续练→修订→历史回看”。同时回归旧曲谱库与曲谱跟练，明确区分文档检查通过和产品测试通过。
