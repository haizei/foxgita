## 1. 开发目标

在现有练习详情页节拍器中交付两项能力：

1. 在 **Speed Sheet** 内通过单一 TAP 按钮测量并显式采用速度；
2. 从 Speed Sheet 进入 **Tempo Ramp Settings**，创建并运行按小节单向升速计划。

完成后必须满足：

- TAP 计算可由注入时钟确定性测试；
- 普通手调、TAP、变速训练只能有一个有效速度控制源；
- TAP 采用、训练开始和阶段升速都在可听见的小节首拍原子生效；
- 音频、Beat Bars 和训练进度来自同一音频时间线，不由 SwiftUI Timer 推算；
- 关闭底部面板不结束训练，离开练习详情页才结束训练；
- 训练计划和结果使用独立 SwiftData 模型持久化；
- 来电等音频中断不会自动恢复播放，App 异常终止后不会偷跑。

## 2. 已确认产品与工程决策

| 主题 | 决策 |
|---|---|
| 信息架构 | A Compact + B Segmented；同一 Speed Sheet 内切换紧凑/扩展状态，不叠加第二个 sheet |
| TAP 入口 | A 中只保留一个 TAP 按钮，不增加“测速”卡片或 Tab |
| TAP 节奏 | 第 2 次有效点击预览，第 4 次起可稳定，静默 0.8 秒进入待采用，2 秒才重置 |
| TAP 生效 | 未播放时立即生效；普通播放时在下一小节首拍生效；训练模式内禁用 |
| 手动调速 | 普通播放时保持快速生效，不强制等待下一小节 |
| 训练方式 | 首版仅单向升速、仅按完成小节数触发 |
| 默认计划 | 当前 BPM → 当前 BPM +20（上限 200），每 4 小节 +5 BPM，预备 1 小节 |
| 目标完成 | 目标 BPM 再完成一个完整阶段后记为完成，并进入目标速度保持 |
| 练习计时 | 启动/暂停变速训练同步启动/暂停 PracticeTimer；退出目标保持后按普通播放规则继续 |
| 节奏快照 | 训练期间锁定拍号、切分和重音；计划使用开始时快照 |
| 预备拍 | 使用当前拍号、重音、音色和音量，只播放每拍主音，不播放切分子拍 |
| 生命周期 | 后台与锁屏继续；主动离开详情页结束并保存；系统中断等待用户恢复 |
| 速度尺 | 引擎保持 40–200；A Compact 的 Tempo Ruler 按 Figma 显示并直接拖动 40–160 |
| 持久化 | Schema V18 新增独立计划和训练结果模型；TAP 原始间隔不落盘 |
| 异常终止 | 下次启动把遗留的运行中记录结算为 `interrupted`，不自动恢复音频 |

本专项取代总 PRD 中以下旧规则：不按秒升速、`start == target` 不可开始、首版无自动降速/往返、“暂停后从半小节续接”改为从下一完整小节开始。ADR-0001 的 Speed/Meter 分离继续有效，仅其中“TAP 延后”被本功能终止。

## 3. 现状与根因

### 3.1 当前调用链

```text
PracticeDetailView
├─ @State MetronomeEngine
├─ @State PracticeTimer
├─ MetronomeDisplayCard
│   └─ 点击 speed → MetronomeSheetAnchor.speed
└─ .sheet → MetronomeSpeedSheet
    ├─ ± → MetronomeEngine.bump
    └─ Tempo Ruler → MetronomeEngine.setBpm

MetronomeEngine
└─ AVAudioEngine + AVAudioPlayerNode
    ├─ 50 ms pump
    └─ 向未来约 150 ms 预排 click buffer
```

现有 Speed Sheet 仅有 BPM 大字、± 和 40–160 Tempo Ruler。UI 直接修改 `MetronomeEngine`，没有 TAP 状态、训练状态或速度仲裁层。

### 3.2 当前实现不能直接满足需求的原因

1. `setBpm` 立即改属性，而约 150 ms 的未来 click 已经排入播放器，不能保证下一小节首拍原子切速；
2. `currentBeatInBar` 在 click 被“排程”时提前更新，不代表用户实际听到的拍点，不能作为阶段计数；
3. `stop()` 会清空 `beatIndex`，无法表达“冻结计划、从下一完整小节恢复”；
4. Sheet 持有的 `@State` 会在关闭时销毁，不能承载持续训练；
5. `AudioSessionCoordinator.onInterruption` 只有 began 回调，无法区分中断开始、结束和路由变化；
6. Schema V17 没有变速计划、训练结果和运行中标记；
7. Tempo Ruler 的 Figma 视觉范围为 40–160，而引擎允许 200；实现必须明确这两个范围而不能误报当前 BPM。

## 4. 范围与非范围

### 4.1 本轮实施

- Speed Sheet 的 TAP 状态与变速训练入口；
- Tempo Ramp Settings 参数编辑、校验、预计时长和开始动作；
- `TapTempoAttempt` 纯状态机与稳健 BPM 算法；
- `MetronomeTempoController` 速度仲裁与训练状态机；
- 音频时间线的小节边界事件和边界命令；
- 0/1/2 小节预备拍；
- 训练运行、暂停、中断、目标阶段、目标保持和结束；
- A Compact Tempo Ruler 40–160，Engine/±/TAP 仍支持 40–200；
- Schema V18、计划/结果 Repository 与异常记录结算；
- 事件埋点、无障碍标识、单元测试、集成测试和关键 UI 测试。

### 4.2 本轮不实施

- 自动降速、往返训练、比例变速、按秒变速；
- 多阶段曲线、跨曲目模板、云同步；
- 麦克风识别 BPM 或保存 TAP 原始时间间隔；
- 静音训练和语音数拍；
- 进程终止后的训练阶段续跑；
- 训练期间动态修改拍号、切分、重音、目标或步长。

### 4.3 发布切片

1. 先用功能开关灰度 TAP，验证稳定率、采用率和误触取消率；
2. 再启用 Tempo Ramp，首版只开放单向按小节升速；
3. Schema V18 必须先通过 V17 真数据迁移测试；关闭功能开关只能隐藏入口，不回退 Schema。

## 5. 领域模型

### 5.1 术语

- **Tap Tempo Attempt**：从第一次有效 TAP 到采用、取消、超时重置或中断的一轮临时采样；不使用 `Session`，避免和持久化 `PracticeSession` 混淆。
- **Tempo Ramp Plan**：一次变速训练的不可变参数和节奏快照。
- **Tempo Ramp Run**：计划开始后的内存运行态；落盘结果称 **Metronome Training Session**。
- **Bar Boundary**：由音频排程时间线产生的下一小节首拍，是训练类速度变更的唯一提交点。
- **Target Hold**：目标阶段完成后，节拍器继续以目标 BPM 播放的训练模式。

### 5.2 值类型

```swift
struct TempoRampPlanValue: Equatable, Sendable {
    let startBpm: Int
    let targetBpm: Int
    let stepBpm: Int
    let intervalBars: Int
    let countInBars: Int
    let meter: MetronomeMeterValue
    let subdivision: MetronomeSubdivision
    let accentPattern: [MetronomeBeatKind]
}

enum TempoRampValidationError: Equatable {
    case bpmOutOfRange
    case targetNotAboveStart
    case unsupportedStep
    case unsupportedInterval
    case unsupportedCountIn
}
```

校验常量：

- BPM：40...200；
- step：1、2、5、10；
- intervalBars：1、2、4、8、16；
- countInBars：0、1、2；
- `targetBpm > startBpm`。

### 5.3 运行状态

```swift
enum TempoRampState: Equatable {
    case idle
    case waitingForStartBoundary
    case countIn(completedBars: Int)
    case running(stage: StageProgress)
    case targetStage(completedBars: Int)
    case targetHold
    case paused(PausedSnapshot)
    case interrupted(PausedSnapshot)
}
```

`TempoRampRun` 至少维护：活动计划快照、当前/下一 BPM、当前阶段已完成小节、最高稳定 BPM、开始时间、暂停次数、中断次数和持久化 session id。UI 不自行维护第二份阶段计数。

## 6. 总体架构

```text
MetronomeSpeedSheet / TempoRampSettingsView / Display Card
                         │ intent + observable state
                         ▼
              MetronomeTempoController
              ├─ TapTempoReducer
              ├─ TempoRampStateMachine
              ├─ TempoRampRepository
              └─ MetronomeAnalytics
                         │ immediate / nextBar commands
                         ▼
                  MetronomeEngine
              ├─ MetronomeTimeline
              ├─ sample-frame scheduler
              └─ audible beat/bar events
                         │
                         ▼
                 AVAudioPlayerNode
```

### 6.1 职责边界

**MetronomeEngine**：拥有音频图、sample-frame 时间线、click 排程、预备拍排程和可听事件；不保存训练计划，不计算 TAP。

**MetronomeTempoController**：由 `PracticeDetailView` 持有，生命周期覆盖整个详情页；统一接收手动、TAP、训练、暂停与中断意图，并把速度命令提交给 Engine。

**TapTempoReducer**：纯逻辑；接收单调时间戳和 timeout action，输出预览/稳定/待采用状态。

**TempoRampStateMachine**：纯逻辑；只消费“已听到的小节边界”、用户动作和中断动作，输出下一条命令和可观察状态。

**TempoRampRepository**：保存最近计划、创建/结束训练结果，并在启动时结算遗留运行记录。

**SwiftUI**：只发送 intent、渲染控制器状态；禁止通过 Timer 或动画完成回调推进小节。

### 6.2 控制器所有权

```swift
@State private var metronome = MetronomeEngine()
@State private var tempoController: MetronomeTempoController
```

`PracticeDetailView` 初始化控制器并注入同一 Engine、Repository、时钟和 analytics。`MetronomeSpeedSheet` 接收 controller，不再直接调用 Engine；Sheet dismiss 不影响 controller。

## 7. 音频时间线与小节边界契约

### 7.1 事件必须描述“可听时间”

新增不可由 `currentBeatInBar` 替代的事件：

```swift
struct MetronomeTimelineEvent: Equatable, Sendable {
    enum Kind { case beat, barBoundary }
    let runToken: Int
    let barIndex: Int
    let beatIndex: Int
    let audibleFrame: AVAudioFramePosition
    let bpm: Int
    let kind: Kind
}
```

Engine 排程 click 时同时登记事件，并根据 `audibleFrame - currentFrame` 延迟发布。发布前校验 `runToken`；stop、重锚或中断后，旧 token 的回调全部失效。Beat Bars、触觉和 Tempo Ramp 共用该事件流。

### 7.2 速度命令

```swift
enum TempoApplicationBoundary {
    case immediate
    case nextScheduledClick
    case nextBar
}

struct TempoCommand {
    let id: UUID
    let source: TempoSource       // manual / tap / ramp
    let bpm: Int
    let boundary: TempoApplicationBoundary
}
```

- 停止态手调/TAP：`immediate`；
- 普通播放手调：`nextScheduledClick`，保持现有快速反馈；
- 普通播放采用 TAP：`nextBar`；
- 训练开始、阶段升速：`nextBar`；
- Ramp 活跃时 controller 拒绝 TAP；手调先显示三选一，不直接提交命令。

### 7.3 边界提交

`nextBar` 命令不得只在 UI 回调时修改 `bpm`。Engine 应在排程到目标 downbeat 前完成以下原子操作：

1. 确认命令 id 仍是当前 pending command；
2. 让目标 downbeat 使用新 BPM；
3. 从该 downbeat 的 sample frame 重新锚定后续 click 间隔；
4. 使旧 epoch/token 的未来 UI 回调失效；
5. 在同一 audible boundary 发布 BPM 和训练状态更新。

实现可选择不超过一个 lookahead 窗口地延迟 future scheduling，或在边界前停止并从目标 frame 重排未播放 buffer；验收以“没有半小节切速、漏拍或重拍”为准，不以具体 AVFoundation 手段为准。

### 7.4 Meter 快照与锁定

计划开始后，Meter Sheet 的拍号、切分和重音控件进入禁用态并解释原因。音色和音量不改变小节结构，可以继续修改。训练结束或退出 Target Hold 后解除锁定。

## 8. TAP 测速

### 8.1 状态

```swift
enum TapTempoState: Equatable {
    case idle
    case sampling(validTapCount: Int, previewBpm: Int?)
    case unstable(validTapCount: Int, previewBpm: Int)
    case stable(validTapCount: Int, bpm: Int)
    case readyToApply(bpm: Int)
    case pendingBoundary(bpm: Int, commandID: UUID)
}
```

进入新 attempt、继续 TAP、取消、采用、sheet 关闭、音频中断都必须取消旧 timeout task，使用 generation token 防止旧异步回调污染新状态。

### 8.2 算法

输入为单调时钟的相邻间隔：

1. 250...1500 ms 为有效区间；无效间隔计入 rejected count，但不进入计算窗口；
2. 最多保留最近 8 次有效 TAP，即 7 个间隔；
3. 计算间隔中位数；
4. 剔除相对中位数偏差大于 20% 的间隔；
5. 对剩余间隔求平均；
6. `round(60_000 / averageMilliseconds)` 得到展示 BPM；
7. 采用时 clamp 到 40...200，并保留越界提示。

第 2 次有效 TAP 可产生 preview；第 4 次有效 TAP 且样本收敛后进入 stable。最后一次有效点击 0.8 秒后进入 ready；若此后继续 TAP，立即撤销 ready 并在同一 attempt 中继续采样。只有相邻有效点击超过 2 秒，下一次点击才清空旧样本并开始新 attempt。

### 8.3 采用与撤销

- 停止态采用：立即更新 Engine BPM、PracticeItem 当前 BPM 和 Ramp 草稿的 start BPM；
- 普通播放采用：创建 nextBar pending command，A 显示“将在下一小节切换为 XX BPM”；
- pending 期间再次 TAP：撤销 pending command，继续当前 attempt；
- 采用结果高于已保存 Ramp target：保留 target，B 显示校验错误，不静默抬高目标；
- Ramp 的 count-in、running、paused、interrupted、targetStage、targetHold 均禁用 TAP。

TAP 只记录汇总埋点，不保存触控时间戳或原始 interval。

## 9. 变速训练状态机

### 9.1 开始

**节拍器停止：**

```text
校验 → 保存最近计划 → 创建 running 结果记录
→ 启动 PracticeTimer → 0/1/2 个 count-in bar
→ start BPM 第一个正式小节
```

预备拍使用计划的 meter/accent 和当前 sound/volume，但 `subdivision = quarter`；不计入正式阶段小节。

**节拍器普通播放中：**

```text
校验 → 保存计划 → 创建 running 结果记录
→ 提交 nextBar(start BPM) → 下一个 downbeat 同时进入 running
```

不重复预备拍；PracticeTimer 已运行则不重启或清零。

### 9.2 阶段推进

- 正式训练的第一个完整小节记为 1；
- 收到 audible bar completed 后增加 `completedBarsInStage`；
- 达到 `intervalBars` 后，提交下一 downbeat 的 Ramp tempo command；
- `nextBpm = min(currentBpm + stepBpm, targetBpm)`；
- command 在 boundary 提交后才把 UI current BPM、阶段和计数一起更新；
- 达到 target 后进入 targetStage，再完成 `intervalBars` 个完整小节才记完成；
- 完成时写 `target_completed`、stableMaxBpm=target，并进入 targetHold；节拍器和计时器继续。

### 9.3 暂停、继续与中断

- 用户暂停：Engine 停止，PracticeTimer 暂停，保存仅含完整小节的 snapshot；半小节丢弃；
- 用户继续：不重复 count-in，从当前阶段 BPM 的新完整小节开始；
- 音频中断 began：进入 interrupted，停止音频、暂停计时、增加 interruptionCount；
- interruption ended：只更新为“可恢复”，不得自动 start；
- 用户确认继续后，从新完整小节恢复；
- App 遗留的 running 记录在下次启动时结算为 `interrupted`，不恢复运行态。

`AudioSessionCoordinator` 应从单一 `onInterruption` closure 改为可注册 observer/token 的事件分发，至少区分 began/ended，避免练习详情、录音和其他消费者相互覆盖回调。

### 9.4 运行中手调

Ramp 活跃时，±、BPM 和 Tempo Ruler 先显示：

1. **仅调整当前阶段**：新值必须在 40...targetBpm；当前阶段计数归零；历史 stableMaxBpm 保留；后续从新值按原 step 升速；
2. **结束变速训练**：结果写 `user_stopped`，保持所选 BPM 进入普通播放，PracticeTimer 继续；
3. **取消**：状态不变。

首版不允许在运行中直接改 target、step、interval 或 meter。进入 B 编辑意味着先暂停；采用新计划后按“新训练”重新开始并执行预备拍。

### 9.5 退出

- 关闭 Speed Sheet/B：训练继续；
- 退出 targetHold：训练结果已完成，转普通播放并开放 TAP/Meter Sheet；
- 主动离开详情：活动训练写 `user_stopped`，停止 Engine、暂停 Timer；
- 点击完成练习：活动训练写 `practice_finished`；
- 后台/锁屏：只要音频 session 可用即继续；音频中断仍按 9.3 处理。

## 10. Schema V18 与持久化

### 10.1 模型边界

新增 `SchemaV18.swift`，完整复制 V17 已发布模型，再增加以下模型；禁止直接修改 V17。

```swift
@Model
final class TempoRampPlan {
    @Attribute(.unique) var id: UUID
    var practiceItemId: UUID
    var startBpm: Int
    var targetBpm: Int
    var stepBpm: Int
    var intervalBars: Int
    var countInBars: Int
    var meterRaw: String
    var subdivisionRaw: Int
    var accentPatternRaw: String
    var createdAt: Date
    var updatedAt: Date
}

@Model
final class MetronomeTrainingSession {
    @Attribute(.unique) var id: UUID
    var practiceItemId: UUID
    var planId: UUID
    var startedAt: Date
    var endedAt: Date?
    var stateRaw: String           // running / completed
    var completionReasonRaw: String?
    var finalBpm: Int
    var stableMaxBpm: Int
    var completedStageCount: Int
    var pauseCount: Int
    var interruptionCount: Int
    var createdAt: Date
    var updatedAt: Date
}
```

首版以 ID 关联，不给 `PracticeItem` 增加反向数组，减少 SwiftData 迁移和删除规则风险。Repository 保证每个 practiceItem 只有一条当前计划：保存新计划时更新已有记录；训练结果按次追加。

### 10.2 保存规则

- B 内编辑值是内存 draft；返回 A 保留；关闭整个 Speed Sheet 丢弃未开始 draft；
- 点击开始、参数校验成功后，upsert 最近计划；
- 同一事务创建 `stateRaw = running` 的训练结果，再启动音频；若音频启动失败，结算为 `interrupted` 并展示错误；
- 每次阶段边界、暂停、中断时更新最小恢复/结算字段；不在每一拍写 SwiftData；
- targetStage 完成时写 `target_completed` 和 endedAt；targetHold 不重复产生结果；
- App 启动时查找残留 running 记录并写 `interrupted`、endedAt=启动时间；
- 删除 PracticeItem 时由 Store 显式删除关联 plan/session；首版不依赖关系级联。

### 10.3 迁移

更新：

- `Models/Models.swift` typealias；
- `GitaMigrationPlan.schemas` 加入 V18；
- `GitaMigrationPlan.stages` 加入 V17 → V18 lightweight migration；
- `foxgitaApp.swift` 使用 V18；
- 所有测试 ModelContainer 加入两个新模型。

V18 只新增模型，预期可使用 lightweight migration。迁移测试必须用 V17 store 写入 PracticeItem 和节拍器设置，迁移后验证旧值无损、新表为空、可新增计划与结果。

## 15. 测试策略

### 15.1 纯单元测试

**TAP：** 250/1500 ms 边界、异常剔除、2/4/8 taps、20% 波动边界、0.8 ready、2s reset、低速 40 BPM 继续点击、generation token、防越界采用。

**Ramp：** 默认值、所有合法枚举、start>=target、不能整除的最后一步、1/4/16 小节、3/4、4/4、6/8、targetStage、targetHold、暂停丢弃半小节、恢复、手调重置阶段、稳定最高值保留。

**Controller：** 普通手调快速生效、TAP nextBar、Ramp 排他、pending 撤销、Meter 锁定、Sound 可改、Sheet dismiss 不结束、离页结束。

### 15.2 Engine 集成测试

- 注入 fake clock/timeline，不依赖 `sleep`；
- pending command 不早于目标 downbeat；
- 同一边界只提交一次；
- epoch/token 失效后无旧 UI 回调；
- 150 ms lookahead 下无旧/新速度混排；
- stop/start、音频中断和路由变化后从完整小节开始。

### 15.3 持久化与迁移

- V17 → V18 旧 PracticeItem/节拍器字段无损；
- 每个 PracticeItem 最近计划 upsert；
- 多条训练结果追加；
- running 遗留记录启动时结算 interrupted；
- targetHold 不重复完成；

## 17. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 已预排 buffer 导致半小节切速 | sample-frame 边界命令、epoch token、Engine 集成测试 |
| UI 比声音提前约 150 ms | 只发布 audible event，Beat Bars 与 Ramp 共用事件流 |
| Sheet 销毁导致训练丢失 | Controller 由 PracticeDetail 持有 |
| 中断回调被其他功能覆盖 | AudioSession 多观察者事件分发 |
| SwiftData 新模型迁移失败 | 不修改 V17；V18 仅新增模型；真实 V17 store 迁移测试 |
| 每拍落盘影响音频 | 只在阶段、暂停、中断、结束时写入 |
| 后台计时与音频状态分离 | AudioSession 事件统一进入 Controller；Timer 跟随训练动作 |
