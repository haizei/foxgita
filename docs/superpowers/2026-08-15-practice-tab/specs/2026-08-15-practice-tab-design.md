# Design: 练习 Tab 产品方案（待练清单 + 按日回顾）

> 功能需求目录：[`../`](../)。本文为设计规格。

**日期：** 2026-08-15  
**状态：** Approved in conversation — awaiting implementation plan  
**范围：** 练习 Tab 的周历列表规则、完成出口、预置任务不再自动出现  
**方案：** 方案 1 — 修练习 Tab；记录 / 历史仍做档案

> **取代：** 「跨天保留今日清单」与底部「本周节奏 → 查看记录」已由 [首页每日练习清空与节奏卡移除](../../2026-08-19-today-practice-empty/specs/2026-08-19-today-practice-empty-design.md) 取代。过去日聚合与「查看」进练习详情的规则仍以本文为准。

---

## 1. 背景与目标

练习 Tab 把「还能练的任务」和「某天练过的记录」叠在同一条周历上，两边规则不一致，表现为三个异常：

1. **8 月 14 日出现多条相同《知足》**  
   过去日按 `PracticeSession` 逐条展示。同一任务完成 6 次（含 0 分钟空完成）就有 6 张卡。
2. **今天（8 月 15 日）冒出「8.5」**  
   今天列表展示全部 `status == .active` 的任务，不过滤来源。预置种籽和自定义任务都会出现；「8.5」是任务标题，不是 8 月 5 日数据串日。
3. **「查看」进了记录页**  
   过去日 `onOpen` 切到记录 Tab。练完详情也会切到记录 Tab。

产品选择（已定）：

| 项 | 选择 |
|---|---|
| 周历心智 | **A**：今天看待练清单，过去看当天已练 |
| 任务从哪来 | 只靠用户创建或从推荐里加入；系统不再每天自动塞预置项 |
| 建过的任务 | **还在**：跨天保留，直到用户删除 |
| 过去日「查看」 | **直接开练**：进练习详情，新记录算今天 |
| 实现幅度 | **方案 1**：只改练习 Tab；记录详情入口不动 |

成功标准：

1. 点过去日：同一任务只一张卡；0 分钟且无笔记/录音的空记录不出现。
2. 点今天：没有系统预置项；只有用户加过的任务。
3. 点「查看」进练习详情并能直接练，不进记录 Tab；练完回到今天的练习列表。

---

## 2. 页面规则

练习 Tab 仍是开练的地方。记录 / 历史仍是档案。周历只切换列表身份。

| 选中日 | 列表 | 主操作 | 禁止 |
|---|---|---|---|
| **今天** | 待练清单：用户创建或从推荐加入的 `TaskItem` | 「开始」→ 练习详情 | 系统不自动塞预置项 |
| **过去** | 当天已练：按任务合成一张卡，写合计分钟 | 「查看」→ 该任务练习详情，直接能练 | 不在过去日新建；新记录记在**今天** |
| **未来** | 空态「还没到」 | 无 | 不能加、不能练 |

不变：

- 底栏四 Tab：练习 / 记录 / 历史 / 设置。
- FAB「＋」只在今天出现。
- 底部「本周节奏 → 查看记录」仍切到记录 Tab。
- 记录 Tab「查看详情」仍进记录详情。

---

## 3. 数据与列表规则

不改 SwiftData Schema。仍用 `TaskItem`（待练）和 `PracticeSession`（某次完成）。

### 3.1 今天：谁能进待练清单

收入条件（同时满足）：

- `isTemplate == false`
- `deletedAt == nil`
- `status == .active`
- **来源是用户加入的**：`id` 以 `custom-` 开头（手建或拍照生成），或 `id` 以 `active-` 开头（从推荐模板激活）

排除：

- 首次安装种籽：`warm` / `chord` / `rhythm` / `song` / `four-done` 等非上述前缀的预置 id
- 模板本身（`isTemplate == true`）只出现在推荐 Sheet，不进今天列表

跨天：满足条件的任务第二天仍在，直到左滑删除（软删）。删除后历史 session 保留。

「8.5」：若 id 符合用户加入规则则保留；若是预置/误种则从今天列表消失。

### 3.2 过去：怎么合成一张卡

对选中日，取 `deletedAt == nil` 且 `endedAt` 在当天的 session，再筛 **有效记录**，按 `taskId` 分组：

| 字段 | 规则 |
|---|---|
| 标题 | 该组最新一条的 `taskTitle` |
| 已练分钟 | 有效记录的 `durationMinutes` 之和 |
| 点「查看」用的 taskId | 分组键 |

**有效记录：** `durationSec > 0`，**或** `noteText` 非空，**或** 至少一条录音/视频。

无效记录（0 分钟且无笔记、无录音）不展示，不计入分钟，不点亮「这天练过」。

### 3.3 连续日 / 本周 n/7

`StatsAggregator` 只认有效记录。空点完成不再点亮周历点、不增加连续日、不计入本周已练天数。

## 4. 导航与完成

练习详情页本身不改（节拍器、计时、步骤、录音/笔记）。改入口和出口。

### 4.1 入口

| 来源 | 行为 |
|---|---|
| 今天「开始」 | `practicePath.append(.detail(taskId))`，计时从 0 |
| 过去日「查看」 | 同上，同一套详情，立刻能练 |
| 任务已软删 | 过去日卡仍在；点「查看」Toast「练习已删除，无法再练」，不进详情 |
| 记录「查看详情」 | 不变，进 `RecordDetailView` |
| 底部「查看记录」 | 不变，`selectedTab = .record` |
| 提醒深链 | 仍打开今天清单第一项；清单空则停在今天空态 |

不管周历停在哪天，这次练完的 session 的 `endedAt` 是完成时刻，因此记在**今天**。

### 4.2 出口

| 情况 | 行为 |
|---|---|
| 「完成」且写入成功 | 清空 `practicePath`，`selectedDay` 回到今天，停在练习 Tab。**不**切记录 Tab |
| 没开计时、也没笔记/录音就点完成 | **不落库**；Toast「这次没有留下记录」；回今天列表 |
| 计时中返回 | 仍二次确认；放弃不落库 |
| 写入失败 | 留在详情，现有 Toast，不切 Tab |
| 连点「完成」 | 一次写入只接受一次；详情关闭后按钮不可再提交 |

### 4.3 推荐 Sheet（＋）

- 只在今天出现。
- 从推荐挑模板 → `activateTemplate` → 加入待练并打开详情。
- 手填名称或拍照生成 → `createCustomTask` / `createFromAIDraft` → 同上。
- **安装时不再把种籽任务写入今天清单。** 新用户今天为空，靠「＋」开始。推荐 Sheet 里的模板仍在。

## 5. 升级与种籽

现有用户：

1. **不软删**预置种籽（`warm` / `chord` / `rhythm` / `song` / `four-done`）。今天列表按 §3.1 前缀规则排除它们，记录 Tab 维持现状（方案 1 不改记录）。
2. 它们已产生的有效 session **保留**，过去日仍能聚合成卡。
3. 用户自己建的 `custom-*` / `active-*` 不动。
4. 种籽标记（`gita.seeded.v2`）保留，避免再次种预置任务；`seedIfNeeded` 改为只种 **模板**，不再种 `todayTasks()`。

新用户：

- 只种推荐模板（`isTemplate == true`）。
- 今天列表为空，直到用户「＋」。

`resetAll`（设置里清数据）与新用户相同：只种模板，不种今天预置项。

## 6. 组件职责

| 单元 | 职责 | 依赖 |
|---|---|---|
| `PracticeView` | 按选中日切换待练 / 聚合已练 / 未来空态；完成回今天 | `PracticeStore`、`AppRouter`、`@Query` |
| `DaySessionCard` / 聚合行 | 展示合计分钟；「查看」回传 `taskId` | 聚合结果，不是原始 session 数组 |
| `PracticeDetailView` | 跟练；完成调用 store；成功后不切记录 Tab | `PracticeStore`、`AppRouter` |
| `PracticeStore.finishSession` | 拒绝无效记录（0 秒且无笔记/录音）；有效才落库 | `PracticeRepository` |
| `PracticeStore.seedIfNeeded` / `resetAll` | 只种模板 | `SeedData.templates()` |
| `StatsAggregator` | 连续日、周点、本周天数只认有效记录 | session 字段 |
| `RecordView` / `HistoryView` | 本方案不改入口 | — |

有效记录判断放在一处（Store 写入 + Aggregator 读取共用同一谓词），避免列表和周历口径分叉。

---

## 7. 错误与边界

| 场景 | 处理 |
|---|---|
| 完成时任务已被删 | `finishSession` 现有 `.notFound`；留在详情 Toast |
| 完成窗口非法（结束早于开始） | 现有 `.invalidInput`；不落库 |
| 过去日点查看但任务已删 | 不进详情；Toast「练习已删除，无法再练」 |
| 同一毫秒连点完成 | 详情在发出完成后再忽略点击，直到关闭 |
| 有效记录仅有笔记、时长为 0 | 落库；过去日卡显示「已练 0 分钟」；该日算练过 |
| 聚合后 task 还在 | 「查看」开练，新 session 记今天 |

## 8. 测试

单测（Swift Testing）：

- `finishSession` 拒绝 0 秒且无笔记/录音；有笔记或录音则接受。
- `seedIfNeeded` / `resetAll` 不写入 `todayTasks()` 种籽，只写入模板。
- 有效记录谓词：0 秒无附件 → 无效；60 秒 → 有效；0 秒有笔记 → 有效。
- 按日聚合：同一 `taskId` 当天 6 条（2 条有效 1 分钟 + 4 条无效）→ 1 组、合计 2 分钟。
- 连续日：只有无效记录的日子不点亮、不断档计算。

UI 冒烟（可扩现有 `PracticeFlowUITests`）：

- 今天列表无预置种籽标题。
- 过去日「查看」停在练习详情，不出现记录 Tab 标题「练习记录」。
- 完成有效练习后仍在练习 Tab，周历在今天。

---

## 9. 非目标

- 不改记录详情、历史月历、统计图。
- 不做按天计划（方案 B），不做今天「待练 / 已练」两段（方案 3）。
- 不改云同步。
- 不改练习详情内部的节拍器 / 录音 / 笔记交互。
- 不把记录 Tab「查看详情」改成练习页。

---

## 10. 对三个异常的结果

| 异常 | 结果 |
|---|---|
| 14 号很多条 | 同一《知足》一张卡；空完成不出现 |
| 今天冒出「8.5」 | 预置/误种不再出现；用户自己建的才会在 |
| 「查看」进记录 | 进练习详情直接开练；练完回今天练习列表 |
