> 日期：2026-08-26

> 对应产品文档：`../../../../design-boards/产品理念/Gita-练习主页设计理念.md`

## 1. 开发目标

将练习主页的数据源从“跨天 TaskItem + PracticeSession 聚合”切换为“按自然日保存的 PracticeItem”。

实现后：

- 每张主页卡片就是某一天真实存在的一条练习项；
- 练习时间直接保存在该练习项；
- 周历、打卡、当天列表和当天总时间都直接读取练习项；
- 保存只更新当前练习项，不创建 Session；
- 过去日期的练习项不会被继续到今天，也不会因浏览而改变日期；
- 同一页面重复保存不会重复增加时间或生成新卡片。

本开发文档不定义练习项目，不增加 `projectId`，也不实现项目聚合。

## 2. 现状与根因

### 2.1 当前数据职责

现有代码存在两层练习对象：

```text
TaskItem
├── 模板
├── 跨天激活任务
├── 默认 BPM / 步骤
└── startedOn 决定今天是否展示

PracticeSession
├── 实际练习时间
├── 日期
├── 笔记
├── 录音 / 录像
└── AI 复盘
```

主页今天列表读取 `TaskItem`，过去日期列表和周历读取 `PracticeSession`。同一个用户行为因此被两个模型共同表达。

### 2.2 当前错误链路

当前 `PracticeDetailView` 会把最近一条有效 Session 恢复为 `openSessionId`。页面离开时再次保存，并更新 Session 的 `endedAt`。因此浏览历史可能改变历史所属日期。

当前主页还存在以下耦合：

- `PracticeView.activeTasks` 通过 `TaskItem.startedOn` 判断今天可见；
- `PracticeView.dayGroups` 按 `PracticeSession.taskId` 聚合过去日期；
- `StatsAggregator.weekDays` 通过 Session 判断打卡；
- `PracticeStore.finishSession` 新建实际练习；
- `RecordingRef` 只能归属 Session；
- `RecordView`、`HistoryView` 和复盘服务仍依赖 Session。

### 2.3 根本改造原则

不在现有 `TaskItem` 上继续追加日级字段。

理由：

1. `TaskItem` 同时承载模板和跨天任务，语义与新 PracticeItem 冲突；
2. 原地改义会让旧数据无法判断是模板、计划还是实际练习；
3. 录音关系和 Session 迁移需要兼容期；
4. 新增独立模型更容易逐页切换并回滚。

因此采用：

> Schema V9 新增 `PracticeItem`，旧 `TaskItem / PracticeSession` 暂时保留为 Legacy 数据。

本轮可以完成代码开发与新数据链路验证，但不能在旧数据迁移方案缺失时直接面向已有用户发布。

原因：新主页只读取 PracticeItem，旧数据仍位于 TaskItem / Session。如果没有迁移，升级用户会看到空主页。

发布前必须二选一：

1. 完成独立的旧数据迁移方案；
2. 明确该构建只用于全新安装和内部测试。

## 4. Schema V9

### 4.1 新模型 PracticeItem

建议新增文件：

```text
foxgita/foxgita/Models/SchemaV9.swift
```

模型定义：

```swift
@Model
final class PracticeItem {
    #Index<PracticeItem>([\.profileId, \.practiceDayKey], [\.updatedAt])

    @Attribute(.unique) var id: String
    var profileId: String
    var practiceDayKey: String

    var title: String
    var categoryRaw: String
    var durationSec: Int
    var bpm: Int
    var timeSig: String
    var stepsRaw: String
    var noteText: String

    var sourceRaw: String
    var originKey: String

    @Relationship(
        deleteRule: .cascade,
        inverse: \RecordingRef.practiceItem
    )
    var recordings: [RecordingRef]

    var createdAt: Date
    var updatedAt: Date
    var deletedAt: Date?
    var syncStateRaw: String
}
```

### 4.2 为什么使用 practiceDayKey

`practiceDay` 使用固定本地日键：

```text
2026-08-25
```

不直接依赖 `Date` 的时区解释，避免用户切换时区后历史练习移动到前一天或后一天。

统一通过纯函数生成：

```swift
PracticeDayKey.make(date:calendar:) -> String
```

规则：

- 创建时写入；
- 后续保存不得自动修改；
- 历史编辑不得修改；
- 查询日期时使用同一 Calendar 生成 key；
- 解析失败的数据不进入主页，并记录可诊断错误。

### 4.3 有效练习项

新增纯规则：

```swift
enum PracticeItemRules {
    static func isEffective(
        durationSec: Int,
        noteText: String,
        recordingCount: Int
    ) -> Bool
}
```

有效条件：

```text
durationSec > 0
OR noteText 去空白后非空
OR 存在未删除媒体
```

不要依赖标题、步骤或 `updatedAt` 判断是否打卡。

### 4.4 时间显示

模型保存精确秒数，列表展示继续沿用向上取整分钟：

```swift
var durationMinutes: Int {
    guard durationSec > 0 else { return 0 }
    return max(1, Int(ceil(Double(durationSec) / 60)))
}
```

当天总时间必须先汇总秒数，再统一转换分钟，避免每项分别向上取整造成总计膨胀。

### 4.5 旧模型兼容

V9 暂时保留：

- `TaskItem`；
- `PracticeSession`；
- `RecordingRef.session`。

`RecordingRef` 新增：

```swift
var practiceItem: PracticeItem?
```

约束：

- 新录音只写 `practiceItem`；
- 旧录音继续保留 `session`；
- 同一 RecordingRef 不允许同时属于二者；
- 媒体查询优先读 `practiceItem`，再兼容 `session`；
- 本轮不删除旧 Session，防止级联删除媒体。

### 4.6 Schema 与迁移计划

更新：

```text
foxgita/foxgita/Models/Models.swift
foxgita/foxgita/foxgitaApp.swift
```

要求：

- typealias 指向 V9；
- `GitaMigrationPlan.schemas` 加入 V9；
- V8 → V9 使用 lightweight migration；
- 新增模型和可选关系必须提供默认值或可空值；
- 旧模型不能在本阶段从 Schema 删除。

## 5. Repository 设计

### 5.1 新接口

在 `PracticeRepository` 增加：

```swift
func practiceItems() throws -> [PracticeItem]
func practiceItem(id: String) throws -> PracticeItem?
func practiceItems(dayKey: String, profileId: String) throws -> [PracticeItem]
func livePracticeItem(
    dayKey: String,
    normalizedTitle: String,
    profileId: String
) throws -> PracticeItem?
func add(_ item: PracticeItem) throws
```

Repository 返回未软删数据。有效性过滤由规则层完成，避免把带笔记或媒体但时长为 0 的有效项错误排除。

### 5.2 查询排序

日期列表排序：

```text
updatedAt DESC
createdAt DESC
```

正在计时的置顶属于 ViewState，不写入持久化排序字段。

### 5.3 同日去重

新增：

```swift
PracticeTitleNormalizer.normalize(_ title: String) -> String
```

最小规范化：

- 去除首尾空白；
- 连续空白折叠；
- 英文字母小写；
- 统一全角与半角空格。

创建前按以下条件查重：

```text
profileId + practiceDayKey + normalizedTitle
```

默认返回已有 item id。只有用户明确选择“仍然新建”时才跳过去重。

`originKey` 继续负责同一次 AI / 图片生成请求的幂等，标题去重不能替代请求幂等。

## 6. Store 命令设计

### 6.1 创建

新增：

```swift
func createPracticeItem(
    title: String,
    category: PracticeCategory,
    bpm: Int,
    timeSig: String,
    steps: [String],
    source: PracticeItemSource,
    originKey: String = "",
    allowDuplicate: Bool = false,
    now: Date = .now,
    calendar: Calendar = .current
) -> PracticeItemCreationResult
```

返回值必须区分：

```swift
enum PracticeItemCreationResult {
    case created(id: String)
    case existing(id: String)
    case failed(StoreError)
}
```

这样 UI 可以在命中同日重复项时直接打开原项，并给出轻提示，而不是再次插入。

### 6.2 保存采用绝对值

不要实现：

```swift
item.durationSec += elapsedSec
```

该写法在重复点击、`onDisappear` 二次调用和后台恢复时都会重复累计。

Store 接收页面计算好的总秒数并执行赋值：

```swift
func savePracticeItem(
    id: String,
    totalDurationSec: Int,
    bpm: Int,
    steps: [String],
    noteText: String,
    now: Date = .now
) -> Bool
```

内部规则：

- `durationSec = max(0, totalDurationSec)`；
- BPM 限制在 40...200；
- 不修改 `practiceDayKey`；
- 实际字段没有变化时不更新 `updatedAt`；
- 重复传入同一 payload 为 no-op；
- 保存失败回滚并保留页面状态。

### 6.3 页面计时基准

进入详情时：

```text
baseDurationSec = item.durationSec
visitElapsedSec = 0
displayDurationSec = baseDurationSec + visitElapsedSec
```

保存时传入 `displayDurationSec`。保存成功后：

```text
baseDurationSec = displayDurationSec
visitElapsedSec = 0
```

这样同一 payload 保存两次仍是相同绝对值。

### 6.4 空练习项

创建后允许短暂存在空 PracticeItem，以便先获得稳定 ID 并挂载媒体。

离开详情时：

- 有效：保存；
- 无效且本次新建：软删除；
- 无效但属于历史旧项：不自动删除，只有用户显式删除才处理。

需要在 View 中保存 `wasCreatedThisVisit`，不能仅根据内容为空决定删除历史数据。

### 6.5 媒体

替换 Session 媒体命令：

```swift
func appendRecording(itemId: String, clip: AudioRecorderService.Clip) -> Bool
```

流程：

1. 校验文件存在；
2. 查找 PracticeItem；
3. 创建 RecordingRef；
4. 追加到 `item.recordings`；
5. 与 item 同一 context 保存；
6. 失败时回滚，不 detach 临时文件；
7. 成功后再 detach recorder pending clip。

录音本身即可使 item 有效并触发当天打卡。

### 6.6 删除

主页练习项使用软删除：

```swift
func softDeletePracticeItem(_ id: String)
```

软删除后立即从日期列表、总时间和打卡状态排除。媒体文件暂不物理删除，由 GC 依据仍被引用的 RecordingRef 处理。

## 7. 主页查询与状态

### 7.1 PracticeView 数据源

移除：

```swift
@Query var tasks: [TaskItem]
@Query var sessions: [PracticeSession]
```

替换为：

```swift
@Query(
    filter: #Predicate<PracticeItem> { $0.deletedAt == nil },
    sort: \PracticeItem.updatedAt,
    order: .reverse
)
private var allItems: [PracticeItem]
```

派生数据：

```text
selectedItems = allItems
  .filter(profileId)
  .filter(practiceDayKey == selectedDayKey)
  .filter(isEffective)

selectedTotalSec = SUM(selectedItems.durationSec)
```

### 7.2 今天与过去日期共用列表

删除 today / past 两套不同对象的渲染方式。

今天和过去日期都渲染 `PracticeItemRow`：

```text
今天：允许打开、编辑、删除、添加
过去：允许打开、修正、删除；不显示添加
未来：只显示锁定空状态
```

不再使用：

- `activeTasks`；
- `dayGroups`；
- `SwipeableTaskRow`；
- `DaySessionCard`；
- `openPastGroup`。

新增统一组件：

```swift
PracticeItemRow(
    item: PracticeItem,
    mode: .today | .history,
    onOpen: ...,
    onEdit: ...,
    onDelete: ...
)
```

### 7.3 区域标题

```text
今天：今日练习 · N 项 · X 分钟
过去：当天练习 · N 项 · X 分钟
未来：尚未到来 · 先练今天
```

`N 项` 是当天练习项数量，不命名为练习次数。

### 7.4 日历

将 `StreakCard` 拆为不含 streak 的 `PracticeCalendarCard`。

输入从 sessions 改为：

```swift
practicedDayKeys: Set<String>
```

保留：

- 周切换；
- 今天状态；
- 未来锁定；
- 已练圆点；
- 日期选择。

移除：

- 连续天数；
- 本周次数；
- Session 参数；
- `weekDone` 文案。

### 7.5 FAB

仅在今天显示添加按钮。过去和未来日期隐藏。

创建成功或命中同日已有项后，统一导航到：

```swift
PracticeRoute.detail(itemId: id)
```

## 8. 练习详情改造

### 8.1 路由

将路由参数从 `taskId` 改为 `itemId`。

```swift
enum PracticeRoute {
    case detail(itemId: String)
}
```

`PracticeDetailView` 只查询一个 PracticeItem，不再查询 TaskItem 与 Session 集合。

### 8.2 移除 Session 状态

删除：

- `@Query sessions`；
- `openSessionId`；
- `resumeState`；
- `PracticeResumeQuery` 调用；
- `PracticeResumeSkipStore` 调用；
- `beginOpenSession`；
- `updateOpenSession`；
- `finishSession`；
- `persistVisit` 的 Session 分支；
- `lastCompletedSessionId` 相关路由状态。

### 8.3 今日模式

当 `item.practiceDayKey == todayKey`：

- 允许计时；
- 允许录音和录像；
- 允许编辑 BPM、步骤、笔记；
- 保存更新同一 item；
- 完成按钮改为“保存并返回”，避免暗示创建一次记录。

### 8.4 历史模式

当 `item.practiceDayKey != todayKey`：

- 默认不启动计时；
- 隐藏“开始计时”与录制入口；
- 展示已保存时间、BPM、步骤、笔记和媒体；
- 允许通过明确的“编辑记录”入口修正；
- 返回和 `onDisappear` 不能自动写入；
- 不修改 dayKey；
- 不提供“继续到今天”。

历史编辑时间使用明确的分钟输入或 Stepper，不复用实时计时器。

### 8.5 onDisappear

`onDisappear` 只执行两类动作：

1. 停止音频、视频、节拍器等运行资源；
2. 当页面确有未保存变更时，调用一次幂等保存。

禁止无条件 touch item。浏览历史后直接返回必须是零写入。

## 9. 添加练习链路

### 9.1 自定义练习

`RecommendSheet` 的“创建练习”改调 `createPracticeItem`。

新 item 初始值：

```text
practiceDayKey = todayKey
durationSec = 0
bpm = 80 或用户选择值
steps = ["新步骤"]
noteText = ""
recordings = []
```

原 `targetMin` 可继续作为添加页的 UI 参考，但不得写成实际 `durationSec`。若本轮不再展示目标时间，应从添加页删除该控件，避免“目标 10 分钟”与“实际 0 分钟”混淆。

### 9.2 模板

旧 TaskItem 模板可以暂时作为创建来源，但不能直接成为主页卡片。

点击模板时：

```text
读取模板内容
→ 创建今天的 PracticeItem
→ 导航到新 item
```

不要继续调用 `activateTemplate` 或生成稳定跨天 active task id。

### 9.3 AI / 图片生成

`PhotoPracticeSheet` 与 `NextSessionSheet` 改为创建 PracticeItem。

要求：

- `originKey` 保证同一次生成请求幂等；
- 同日同标题命中已有项时默认打开已有项；
- 不调用 `ensureForToday`；
- 不复用前一天生成的 item；
- 跨天重复生成时创建当天新 item。

foxgita/foxgita/Services/PracticeItemQuery.swift

纯函数：

- `weekDays(from sessions:)`；

暂不删除这些函数，因为 Record / History 仍在使用。新增 PracticeItem 版本或把周历日期构造抽成不依赖业务模型的纯函数。

## 11. Router 清理

检查并移除练习主页链路中的 Session 状态：

- `lastCompletedSessionId`；
- `clearJustCompleted()`；
- Session 成果卡导航；
- `returnPracticeToToday` 中对完成 Session 的假设。

保留：

- 选择练习 Tab；
- 清空详情栈；
- 通知打开今天第一条练习项。

提醒通知触发时，如果今天没有 PracticeItem，只切到练习首页，不自动创建练习项。

## 12. 媒体与 AI 复盘兼容

现有复盘服务通过 RecordingRef 反查 Session，再获取标题、步骤、BPM 和笔记。改造后：

```text
优先：RecordingRef.practiceItem
兼容：RecordingRef.session
```

建议新增统一上下文转换：

```swift
MediaReviewContextFactory.make(recording:)
```

避免 `PracticeStore.reviewContext` 中继续硬编码 Session。

新 PracticeItem 的复盘上下文直接读取：

- item.title；
- item.steps；
- item.bpm；
- item.timeSig；
- item.noteText。

旧录音仍从 Session 读取，直到迁移完成。

## 13. 旧数据与迁移策略

### 13.1 本轮原则

本产品文档明确把数据迁移排除在主页设计范围外，因此本开发阶段不得擅自用不可靠规则合并旧数据。

尤其不能直接：

- 按标题合并不同任务；
- 假设同 taskId 同一天的多个 Session 都是重复；
- 对多个 Session 时长无条件求和或取最大值；
- 删除旧 TaskItem / Session；
- 移动媒体后立即删除原关系。

### 13.2 推荐后续迁移输入

迁移文档需要单独决定：

```text
旧 Session → 新 PracticeItem
```

至少处理：

- 同 taskId 同日多 Session 如何合并；
- 已知重复保存导致的异常 Session；
- 标题被编辑后的快照选择；
- 时长求和与去重策略；
- 笔记合并策略；
- 媒体转移；
- 软删任务但 Session 保留；
- 时区与 `endedAt` 转 dayKey；
- 迁移幂等和回滚。

### 13.3 迁移技术门槛

V8 → V9 的 Schema migration 只负责新增模型和关系。旧数据转换建议使用独立的一次性 application migrator，并具备：

- 明确版本 key；
- 可重复运行且不生成重复 item；
- 迁移前后数量与总时长审计；
- 失败不删除旧数据；
- DEBUG 预览与日志；
- 单独的 MigrationTests。

## 18. 风险与对策

### 风险 1：Record / History 与新主页数据分裂

新 PracticeItem 不会自动出现在仍读取 Session 的 Record / History Tab。

对策：本轮构建标记为开发版本；正式发布前完成下游页面方案，或临时隐藏无法反映新数据的入口。不能让用户以为数据丢失。

### 风险 2：媒体关系迁移导致丢文件

对策：V9 保留旧 session 关系，新媒体写 item；GC 同时收集两种关系引用。旧关系删除前必须有媒体数量与文件存在性审计。

### 风险 3：标题去重误合并

对策：只在同一天默认复用，并允许用户明确“仍然新建”；不跨天、不跨 profile 自动合并。

### 风险 4：分钟显示与总时间不一致

对策：所有计算先按秒汇总，再格式化；禁止对每项取整后求和。

### 风险 5：页面生命周期重复保存

对策：Store 接受绝对总时长；无变化 no-op；`onDisappear` 只在 dirty 时调用。

### 风险 6：空项清理误删历史

对策：只自动清理本次新建且仍无效的 item，历史 item 必须显式删除。

## 19. 完成定义

满足以下条件，本轮开发才算完成：

- 新 PracticeItem 是练习主页唯一业务数据源；
- 主页不查询或聚合 PracticeSession；
- 保存不会创建 PracticeSession；
- 同一 item 重复保存绝对幂等；
- 日期、打卡、总时间直接由 PracticeItem 计算；
- 历史浏览不写数据；
- 新录音可直接归属 PracticeItem；
- V8 → V9 升级不丢旧数据；
- 产品文档 8 条 AC 均有自动化覆盖；
- 明确记录迁移与正式发布阻塞项。

## 20. 最终工程表达

```text
添加今天的 PracticeItem
→ 详情直接编辑该 Item
→ 计时结果以绝对值写回 durationSec
→ 周历和日期列表直接查询 PracticeItem
→ 不创建 Session
→ 不跨天修改 Item
```

工程上的核心约束是：

> **PracticeItem 既是主页卡片，也是当天真实练习数据；任何保存、浏览和导航行为都不能再制造第二层练习事实。**
